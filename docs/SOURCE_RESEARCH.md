# 소스 조사 기록 — 당근알바

## 기존 Chrome 로그인 연결 (2026-10-16)

사용자가 Chrome 슬롯 1의 로그인을 지정해 실제 홈의 채팅 접근성 이름 `채팅`과 로그인 상태를 확인했다. 이를 기존 설치 앱에 연결하기 위해 수동 설치형 companion 확장을 추가한다. 사용자 클릭의 activeTab/scripting으로 현재 당근 탭만 읽고 별도 로컬 브리지로 상태/미읽음/순서 3값만 전달한다. 사이트에 새 수집 API·요청을 만들거나 지원·채팅을 송신하지 않는다. 이 연결은 공개 소스 수집기의 robots·예산·인증 경계를 바꾸지 않는다. 기능과 권한·검증의 구분은 `CHROME_MESSAGE_CONNECTION.md`를 따른다. 실제 확장 설치·새 메시지 수신은 사용자 권한 확인 이후 별도 검증이다.

## 지원·메시지 추가 조사 (2026-10-16)

사용자가 자동 지원과 새 메시지 알림의 조사/구현을 요청한 뒤 ‘확인 필요 포함·불확실 조건 제출 보류’, ‘기존 정보로 초안만’으로 선택했다. 현재는 초안 전용이며 실제 지원 POST/계정 API/약관 동의/채팅 송신은 하지 않는다. 공개 수집기의 robots·예산·호스트 범위를 변경하지 않았다.

REA의 격리 Edge에서 공개 상세 `지원하기`→공식 계정 로그인 이동을 관찰했다. 배포 JS에서 본인인증·앱 전용 지원·추가 입력·자기소개/약관 분기, 채팅 웹소켓/브라우저 알림 코드와 헤더의 `채팅, 읽지 않은 메시지 N개` 표시를 확인했다. 사용자 시작형 전용 Edge는 이 **보이는 표시**만 읽으며 비공개 API/소켓을 직접 재현하지 않는다. 로그인 입력은 사용자 소유이며 기존 세션을 복사하지 않는다. 메시지 본문은 저장하지 않는다.

실제 로그인 후 폼·새 메시지 수신·제출 완료는 아직 미검증이다. 정적 코드와 합성 DOM 검증은 실계정 성공이 아니다. 근거와 부분 분석 한계, 구현 계약은 `LEAD_OPPORTUNITY_AUDIT_20261016.md`에 기록했다.

## 발견 지연 보완 (2026-10-16)

`LEAD_FRESHNESS_AUDIT_20261016.md` 조사 후 사용자 승인으로 신규 ID 우선·공개 목록 최초 관찰 기록·상세/상품/소개 페이지 제작 요청 보완·30분 감시를 구현했다. 일일 300회와 6초 간격은 유지하고 감시당 상세 HTTP 4회(기존 갱신 1회 포함), 자동 재확인 2회/실행으로 신규 발견 예산을 확보한다. 미처리 후보는 다음 감시에서 다시 고려한다. 세부 동작·검증·한계는 `LEAD_FRESHNESS_IMPLEMENTATION_20261016.md`에 기록한다.

REA로 공개 지역 검색과 첨부 공고 상세, 관찰한 JS 4개를 분석했으나 전국 검색 전체 페이지·정렬·공식 실시간 피드는 확보하지 못했다. 새 API·인증 경로를 수집기에 도입하지 않는다. 30분 주기는 상류 사이트맵 등재 지연이나 전체 시장 포괄률 보장이 아니다. 최초 관찰은 적용 이후부터 기록한다.

> 이 문서는 수집 허가가 아니다. 공개 열람 가능성과 자동 수집 허용을 같은 것으로 보지 않는다.
> 현재 상태: **전국 공개 공고 사이트맵 기반 탐색 및 상세 HTML 해석 연결**. 설치별 수집 승인 기록 필요. 공개 목록의 범위와 사이트 전체 시장 포괄률은 구별한다.

- 추가 후보는 미확인 글을 먼저, 이미 시도한 글은 오래된 시도부터 순환한다. 수집 화면은 핵심 후보·추가 확인 후보·실제 추가 요청·다음 탐색 보류를 구분한다. 보류 후보의 다음 확인은 남은 예산과 소스 상태에 따라 달라진다.
