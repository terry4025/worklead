# EXAONE 제거 · 자체 지원서 조합기 · 판정 규칙 보강

작성 2026-11-19. 2026-11-10에 설치한 EXAONE 보조 기능(`docs/superpowers/specs/2026-11-09-exaone-ai-assist-design.md`)을 대체한다.

## 1. 의도

- 사용자는 EXAONE을 앞으로 쓰지 않기로 했다. 키를 넣을 수 없었고, 응답이 60~100초 걸리며, 약관상 상업 이용이 막혀 있고 입력이 학습에 쓰인다.
- 자동 지원 문구는 계속 공고마다 맞춰서 나가야 한다. 사용자가 원한 수준: 공고 제목과 본문을 보고 쓴 티가 나고, 포트폴리오 링크가 늘 붙고, 읽은 사람이 "이 사람으로 해 볼까" 하는 글. 이번에는 AI 없이 자체 알고리즘으로 만든다. 사용자가 고른 방식은 "후보 여러 개 → 코드로 채점 → 최고점 제출"이다.
- 수집은 전국 단위로 할 수 있는 일을 빠짐없이 가져와야 한다. 11-10~11-19 점검 결과, 수집 범위는 정상이었다(앵커 99개, 17개 시·도). 구멍은 판정 규칙에 있었다.

## 2. 목표 · 비목표 · 반목표

**목표**
1. EXAONE 코드, 설정, 화면, 데이터를 모두 걷어 낸다. OpenAI 분석은 EXAONE 이전 동작으로 남긴다.
2. 자동 지원은 자체 조합기가 만든 공고별 문구를 기존 `fill` 경로로 넣어 제출한다.
3. 수동 "당근 지원 초안 준비"도 같은 조합기 결과로 시작한다.
4. 개발 의뢰인데 의뢰 표현이 정형이 아니어서 제외되던 공고를 규칙으로 잡아 "검토 필요"로 올린다.
5. 제목 필터가 놓치던 표현(프로그래밍, html, 코드 제작, 봇 설정)을 추가한다.

**비목표**
- 채팅 답장 초안과 견적 초안. EXAONE과 함께 빠지며, 규칙 기반으로 다시 만들지 않는다.
- 맞춤 문구를 끄는 설정(기본 소개로 되돌리기). 요청이 없었다.
- 아이보스와 당근 카페 수집 로직 변경. 카페는 로그아웃 상태라 사용자가 다시 로그인해야 한다.

**반목표** (동작은 하더라도 이렇게 되면 실패다)
- 사용자가 해 본 적 없는 경력, 수치, 약속을 문구에 쓰는 것. 뉴던 원칙상 "약속 − 성과 = 사기"다.
- 모든 공고에 거의 같은 글이 나가서 템플릿 티가 나는 것.
- 규칙으로 "추정"한 공고에 자동 지원이 나가는 것. 추정 건은 사람이 본다.
- 이미 동작하는 수동 승인과 자동 지원 안전장치(해시 대조, 1회 허가, 계정 확인)가 약해지는 것.

## 3. 제약

- 실제 사용자 DB(`%LOCALAPPDATA%\Worklead\worklead.sqlite3`)는 앱을 닫은 상태에서 설치 과정으로만 바꾼다. 데이터 정리는 마이그레이션이 맡는다.
- 확장 프로그램의 7키 작업(`application_text`, `text_hash`), `fill` 동작, 시도별 해시 대조(`_texts`, `_expected_profile`)는 그대로 쓴다. 해시 규칙은 `auto-content.js`의 `norm()`과 같다(공백 접기, 앞뒤 자르기).
- 문구는 2000자 이하여야 한다(`fill` 제한). 목표 길이는 휴대폰 한 화면, 250~600자.
- korean-humanizer는 MIT 라이선스다. 규칙을 코드로 옮길 때 출처를 주석에 남긴다.
- 커밋 트레일러는 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`이다. 작업 트리에 있는 남의 미커밋 변경(`engine/runs.py`, `engine/executors.py`, `tests/test_collector_lanes.py`)은 건드리지 않는다.

## 4. 고려한 접근

| 접근 | 장점 | 단점 |
|---|---|---|
| **A. 자체 조합기 (선택)** | 무료이고 즉시(수 ms) 나온다. 결과가 결정적이라 허가 단계에서 다시 만들어 해시를 비교할 수 있다. 공고를 외부로 보내지 않는다. | 공고 문장을 자연스럽게 바꿔 말하지 못한다. 처음 보는 유형은 분야 기본 문구로 나간다. |
| B. 당근 기본 자기소개 그대로 | 코드가 가장 적다. | 공고별 맞춤이 없다. 사용자 목표와 맞지 않는다. |
| C. 기존 OpenAI 제공자로 생성 | 문장 품질이 가장 높다. | 유료이고 공고를 외부로 보낸다. 응답 대기와 실패 재시도 상태가 다시 생긴다. |

사용자가 A를 골랐다. A는 사용자가 앞서 고른 "병렬 후보 + 코드 채점"을 AI 없이 그대로 구현하는 방법이다.

## 5. 설계

### 5.1 EXAONE 제거

**빠지는 것**
- 백엔드 모듈: `analysis/exaone_provider.py`, `assist.py`, `writer.py`(검증 함수는 조합기로 옮김, 5.2), `recheck.py`, `chat_draft.py`, `prompts.py`(뉴던 원칙은 조합기 문장 은행의 주석과 문장으로 옮김).
- 연결부: 보조 작업자 시작과 깨우기(`server.py`, `context.py`, `chrome_bridge.py`, `auto_apply.next`의 wake), `pipeline.apply_analysis`의 `keep_promotion`, 채팅 초안 라우트(`job_message_routes.py`, `chat_view.py`), 견적 초안 API, EXAONE 자격 증명 슬롯(`services/credentials.py`), 제공자 선택의 EXAONE 분기(`coordinator._analyze_exaone`과 그 호출, `provider.py`·`types.py`·`settings.py`의 `exaone` 값).
- 설정: `ai.daily_call_cap`, `assist_*` 스위치 5개, `exaone_calls`, 프로필의 `price_anchor_note`(견적 초안에만 쓰였다).
- 화면: AI 설정의 EXAONE 선택지, 호출 상한, 보조 스위치, LG 안내문, 메시지함의 답장 초안과 복사, 리드 상세의 견적 초안 패널(`QuoteDraftPanel.tsx`), 설정의 기준가 칸. 계약 파일(`contracts/`)은 백엔드 스키마에서 다시 생성한다.
- 테스트: EXAONE 전용 테스트 파일(`test_exaone_*`, `test_ai_writer`, `test_ai_recheck`, `test_assist_core`, `test_chat_draft`, `test_quote_draft`, `test_auto_apply_ai_path`, `exaone_fixtures.py`, `desktop/src/__tests__/quote-draft.test.tsx`)은 지운다. 섞여 있는 테스트는 EXAONE 부분만 걷는다.

**남는 것**
- `analysis/grounding.py`와 `provider.assist_eligible`. EXAONE 작업 때 OpenAI 쪽에서 떼어 낸 공용 코드라 OpenAI 분석이 계속 쓴다. 시급 검토 리드를 AI 분석 대상에 넣는 변경도 유지한다.
- 포트폴리오 주소(`portfolio_url`), 절전 막기(`collection.prevent_sleep`, `SleepGuard`), 공백 뒤 사이트맵 즉시 읽기, 구글시트·아두이노·코딩 수집어, 확장의 `fill`과 7키 작업, 관리형 Edge의 채우기 흐름, `ai_text_unavailable` 사유 코드. 사유 코드는 과거 기록과 확장이 쓰므로 이름은 두고 화면 문구만 "지원 문구를 만들지 못함"으로 바꾼다.

**데이터 (마이그레이션 0011)**
- `ai_drafts` 테이블과 `leads.ai_recheck` 열을 지운다(SQLite batch).
- `app_settings.ai` 행: 제공자가 `exaone`이면 OpenAI 기본값으로 되돌리고 `enabled=false`로 둔다. `daily_call_cap`과 `assist_*` 키를 지운다. `ai_revision`은 올려서 열려 있던 화면이 낡은 값을 저장하지 못하게 한다.
- `exaone_calls` 행을 지운다.
- 0010 이전 백업의 복원 예외(`storage.validate_database`)는 0011 기준으로 다시 맞춘다. 0010 백업도 복원하면 0011로 올라가야 한다.
- 실행 중인 AI 재확인 승격 리드: `keep_promotion`이 빠지면 다음 재분석 때 규칙이 다시 판단한다. 5.3의 추정 규칙이 잡으면 "검토 필요"로 남는다.

### 5.2 자체 지원서 조합기

새 모듈 두 개: `analysis/composer.py`(추출, 후보 생성, 채점, 검증)와 `analysis/compose_bank.py`(문장 은행. 버전 상수 `BANK_VERSION`을 둔다).

**입력**: 공고 제목, 본문(`SourceRecord.body_text`), 규칙 분석 결과(`categories`, 리스크 근거), 프로필(`portfolio_url`, `business_registered`, `tax_invoice`, `skills`), 리드 id(변주용).

**1단계: 공고 읽기 (추출)**
- 요청 대상: 제목에서 요청 꼬리("도와주실 분", "구합니다", "모십니다", "해 주실 분", "가능하신 분", "찾습니다", 괄호, 이모지, 금액 표기, 느낌표·물결표)를 떼어 낸 명사구. 예: "카페24. 코딩 수정 2시간 도움주실 분 모십니다." → "카페24 코딩 수정". 4~30자가 아니면 분야 이름으로 대신한다.
- 기술·플랫폼 단어: 고정 사전(카페24, 아임웹, 워드프레스, 식스샵, 스마트스토어, 쿠팡, 구글시트, 엑셀, VBA, 매크로, 파이썬, HTML, CSS, 자바스크립트, 리액트, 앱, 안드로이드, 아이폰, API, 크롤링, 챗봇, 자동매매, 키움, 서버, 도메인, 호스팅, 상세페이지, 랜딩, 예약, 결제, 로그인, 관리자, 노션 등)에서 제목과 본문에 나온 것. 제목에 나온 것이 앞선다.
- 작업 종류: 수정(수정, 오류, 에러, 버그, 고쳐, 안 돼요, 옮겨, 이전, 연결)인지 새로 만들기인지.
- 분야 묶음(문장 은행 키): `web_new`(website·landing·fullstack + 새로 만들기), `web_fix`(website·landing·shop + 수정, 또는 플랫폼 이름), `shop_page`(상세페이지·상품등록), `automation`(vba·automation·data, 엑셀·구글시트·매크로·크롤링), `software`(software, 앱, 프로그램, API, 자동매매), `general`(나머지).
- 리스크 신호: AI·OCR(결과가 매번 같지 않음), 증권사·유료 API(계정과 승인 필요), 관리자 계정·비밀번호(메시지로 받지 않음), 결제·개인정보.

**2단계: 후보 만들기**

글은 여섯 칸으로 짠다. 순서는 뉴던 원칙("첫 문장은 요청 핵심 다시 짚기 → 할 수 있는 범위 → 리스크 → 질문 1~2개")을 따른다.

| 칸 | 내용 | 변형 수 |
|---|---|---|
| 1. 짚기 | 요청 대상을 고객 말로 다시 짚는다. "{대상} 건 보고 연락드립니다." 등 | 3~4 |
| 2. 범위 | 분야 묶음별로 무엇을 어떻게 할지. 기술 단어 1~2개를 끼운다. | 묶음마다 3 |
| 3. 리스크 | 리스크 신호가 있을 때만 해당 문장 하나 | 신호마다 2 |
| 4. 질문 | 지금 방식, 가장 불편한 곳, 준비된 자료 중 1~2개 | 묶음마다 3 |
| 5. 소개 | 1인 스튜디오 DCORE LAB, 상담부터 납품까지 직접. 사업자 문장은 설정에 따라 코드가 붙인다(기존 `business_sentence`). | 2 |
| 6. 링크 | "작업 예시: {portfolio_url}" | 1 |

- 칸별 변형을 조합해 후보를 만든다. 조합 수가 200을 넘으면 리드 id로 시드를 고정한 표본 200개만 쓴다.
- 문장 은행의 사실은 사용자가 공개해 둔 것만 쓴다. 출처는 뉴던 `11_DCORELAB_적용안.md`와 크몽 개선안 `프로필_서비스_문구초안.md` 중 `[확인 필요]`가 없는 문장이다. 담는 사실: 홈페이지를 직접 코딩한다, 소스 코드를 넘긴다, 진행 중에 확인 링크로 화면을 보여 준다, 스마트스토어·쿠팡 정산 대조와 송장 변환 자동화를 한다, 안 되는 것은 처음에 말한다. 숫자 실적(리뷰 수, 경력 연수)과 가격·기간은 쓰지 않는다. 프로필의 `skills`가 채워져 있으면 그 문장을 범위 칸 뒤에 한 줄 붙이고, 비어 있으면 은행 문장만 쓴다.
- 은행 문장은 작성 단계에서 humanizer 규칙으로 미리 다듬는다. 줄표, 연결어미 뒤 쉼표, "~를 통해", "~에 대해", 문두 접속사, "결론적으로", 과장어, 이모지, 번호 목록을 쓰지 않는다.

**3단계: 채점**

모든 후보에 점수를 매기고 가장 높은 것을 고른다. 같은 점수면 `sha256(lead_id + 후보 문장 id)`가 작은 쪽을 고른다. 결정적이면서도 공고마다 고르는 문장이 달라진다.

- 더하는 점수
  - 공고 반영도: 추출한 기술·플랫폼 단어와 요청 대상이 글에 나온 비율. 비중이 가장 크다.
  - 질문 1~2개: 0개나 3개 이상이면 깎는다.
  - 문장 길이의 변화: 표준편차가 너무 작으면(humanizer E-1) 깎는다.
- 빼는 점수 (humanizer 분류표를 정규식으로 옮김. 심각도 S1은 3점, S2는 1점)
  - A-1 "~에 대해", A-2 "~를 통해" 반복, A-10 "~할 수 있습니다" 2회 이상, A-11 "~을 위해" 반복
  - C-11 연결어미 직후 쉼표, D-1 결산 접속어, D-6 막연한 긍정 마무리, E-2 같은 종결어미 3문장 연속, H-1 문두 접속사, J-2 줄표·물결표, 이모지
  - 같은 낱말 반복(예: "작업"이 4번 넘게)
  - 길이: 250자 미만, 600자 초과
- 탈락 조건 (점수와 상관없이 버림. 기존 `writer.common_checks`를 옮겨 쓴다)
  - 포트폴리오 외 링크·도메인, 전화번호·이메일, 과장·보장 표현(`BANNED`), 공고와 프로필에 없는 숫자
  - 사업자·세금계산서 표기가 설정과 다름
  - 2000자 초과

**4단계: 결과와 실패**
- `compose(rec, profile, analysis, lead_id) -> str`는 순수 함수다. 같은 입력이면 같은 글이 나온다.
- 모든 후보가 탈락하면(예: 포트폴리오 주소가 비어 있음) `ComposeError`를 낸다. 자동 지원은 그 공고를 `ai_text_unavailable`로 보류하고, 알림을 한 번 보낸다(dedupe 키는 사유+날짜). 결정적이라 다시 시도하지 않는다. 설정을 고치면 다음 판단 때 다시 만든다.

### 5.3 자동 지원 연결

- `auto_apply.condition`: EXAONE 경로(`ai_path`, `SOFT_TEXTS` 허용 목록)를 지운다. 대신 `lead.demand_intent_basis`가 `explicit` 또는 `user_confirmed`일 때만 통과시킨다. 규칙이 추정한 의뢰(5.4)는 자동 지원 대상이 아니다. 지금 있는 구매 의뢰 판정은 모두 `explicit`이라 기존 동작은 바뀌지 않는다.
- `auto_apply._next`: 후보 쿼리에서 `Lead.ai_recheck` 조건을 지운다. `writer.application_draft` 대신 `composer.compose`를 바로 부른다(대기 상태 없음). 성공하면 작업에 `application_text`와 `text_hash`를 넣고 `_texts[row.id]`에 해시를 남긴다. `ComposeError`면 `ai_text_unavailable`로 보류한다.
- `review`와 `permit`: `_draft_current`는 DB의 `AiDraft` 대신 `compose`를 다시 불러 해시를 비교한다. 공고나 프로필이 바뀌었으면 해시가 달라져 허가하지 않는다. `application_text_required` 스위치 검사는 지운다. 관리형 Edge 경로는 늘 맞춤 문구를 쓴다.
- 확장(크롬 연동) 경로: 확장은 7키 작업을 받으면 지금처럼 바로 `held`/`ai_text_unavailable`로 보류한다. 맞춤 문구는 관리형 Edge에서만 나간다. 이 동작은 바꾸지 않는다.
- `mark_used` 같은 AI 초안 사용 기록은 지운다.
- 수동 초안: `jobs/applications.prepare`는 `inquiry_draft` 대신 `compose`를 쓴다. 조합에 실패하면 지금의 `inquiry_draft`로 대신한다. 사용자가 고친 초안을 보존하는 기존 규칙은 그대로다. 카페 댓글 답장(`inquiry_draft(reply=True)`)은 바꾸지 않는다.

## 6. 검증

- 단위 테스트
  - 조합기: 분야 묶음 6개마다 예시 공고, 링크·숫자·사업자 탈락 규칙, 결정성(같은 입력 → 같은 해시), 공고마다 문구 변주, 2000자 상한, 포트폴리오 없음 → `ComposeError`.
  - humanizer 채점: 위반 문장을 넣은 후보가 지는지 확인한다.
  - 추정 규칙: 위 "잡혀야/안 되는" 예시 전부. 추정 건은 자동 지원 `condition`에서 `condition_changed`로 막히는지.
