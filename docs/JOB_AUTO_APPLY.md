# 50점 이상 자동 지원과 빠른 탐색 (2026-10-25)

사용자 지시로 기존 ‘방법 설명/초안 전용’ 범위에서 **Worklead 실행 중 50점 이상 자동 지원**으로 확장했다. 기존 편집 초안 API는 계속 초안 전용이며, 새 자동 지원 실행부는 당근에 저장한 기본 자기소개를 사용한다.

## 작동 흐름

1. 지역 공개 목록에서 신규 제작 의뢰를 발견하고 상세 분석을 저장한다. 전체 탐색 완료까지 기다리지 않고 개별 저장 결과가 목록에 반영된다.
2. 자동 지원 전용 크롬 탭이 Worklead에 약 5초마다 로컬 후보를 확인한다. 기본 **50점 이상(50 포함, 49 제외)**이며 ‘확인 필요’도 포함한다. 모집 중·제작 구매 의뢰·건당 보수·현재 접근 가능·최근 24시간 범위에서 현재 규칙 점수를 재검사한다. 일반 고용/제외/이미 연락·지원한 건은 자동 제출하지 않는다.
3. 선택한 전용 탭이 해당 공고로 이동해 제목·공고 식별자·보이는 계정 표식을 대조한다. ‘지원 취소’가 이미 있으면 기존 지원으로 기록하고 건너뛴다.
4. 첫 ‘지원하기’ 뒤 기본 자기소개가 선택됐다는 표시, 저장된 소개의 일치, 추가 입력/동의 여부를 확인한다. 입력 내용을 자동으로 작성하거나 바꾸지 않는다. 다른 계정·소개·공고·필수 질문으로 바뀌면 보류한다. 소개 비교 중 화면이 바뀌어도 마지막 클릭 전에 동기 대조로 차단한다.
5. 별도 로컬 실행부가 점수·조건·일일 한도를 다시 확인하고 1회 허가를 DB와 별도 중복 방지 기록에 먼저 저장한다. 3초 안에 최종 ‘지원하기’를 한 번 누른다. 저장한 소개로 개별 공고 확인 없이 진행하며, 확인이 필요한 예외만 보류한다.
6. 같은 공고의 **지원 취소 버튼**이 나타난 경우만 제출 확인으로 기록한다. 클릭했다는 사실이나 네트워크 성공 코드만으로 완료 처리하지 않는다. 결과 유실·시간초과·앱/탭 종료는 결과 미확인으로 두고 자동 재제출하지 않는다.

기본 하루 제출 상한은 20건이며 화면에서 1~200 범위로 조절한다. 결과 미확인도 하루 허가 수에 포함해 같은 날 반복 제출이 늘지 않게 한다. 한 공고는 표시 제목/주소가 바뀌거나 DB를 복원해도 이미 발급한 제출 허가를 다시 사용하지 않는다. 완료 확인 건만 영업 상태를 ‘연락함’으로 옮기며 채택·계약·수금과 구분한다.

원격/대면 여부가 원문에 없다는 이유만으로 모든 50점 공고를 일괄 제외하지 않는다. 저장된 소개로 응답 가능한 일반 지원 흐름을 대상으로 하되, 필수 추가 질문·새 동의·본인인증·앱 전용·사업자/세금계산서 필수 충돌·현재 최소 계약금액 미달은 보류한다. 사이트가 다른 지원 화면을 제공하면 인식할 수 있을 때까지 보류한다.

## 처음 연결하기

1. Worklead의 **지원 준비·메시지 → 점수 기준 자동 지원**에서 기본 50점과 하루 상한을 확인하고 시작한다. 앱에 ‘크롬 연결 대기’가 표시되는 것은 실제 지원이 시작됐다는 뜻이 아니다.
2. 사용자 설치용 확장 폴더는 `%LOCALAPPDATA%\Worklead\chrome-message-extension`이다. 크롬 슬롯 1의 `chrome://extensions`에서 기존 확장을 새로고침하거나 압축 해제된 폴더를 불러온다. 이름은 **Worklead 당근 연결**, 버전 `0.2.1`, ID `ljakiellilahkchbfjalkecollnfldoc`이다.
3. 메시지 감시와 **별도의 로그인된 당근알바 탭**을 선택한다. 이 탭은 공고 사이를 자동 이동하므로 다른 용도로 조작하지 않는 편이 좋다.
4. Worklead의 **자동 지원 연결 코드**를 복사해 확장 팝업의 **자동 지원 전용 연결 코드**에 붙여 넣는다. ‘저장된 기본 자기소개로 개별 확인 없이 지원’ 항목을 확인하고 **자동 지원 탭 연결**을 누른다. 코드와 자기소개/계정 정보를 채팅에 보내지 않는다.
5. 선택한 탭 및 이 PC Worklead로의 연결 권한을 크롬에서 확인한다. Worklead 상태가 연결됨으로 바뀌고 최근 관찰이 갱신되는지 확인한다. 실제 제출 확인·보류·결과 미확인은 각각 표시한다.

브라우저 도구는 `chrome://extensions/`를 보안 정책상 열지 못했으므로 위 설치/새로고침과 연결코드 붙여넣기는 사용자가 직접 해야 한다. 레지스트리·프로필·우회 브라우저 명령으로 권한을 대신 주지 않는다. 승인을 다시 받으려는 단계가 아니라 도구로 조작할 수 없는 설치 화면이다.

## 실행·중지·재시작

Worklead와 크롬이 모두 실행되고 전용 탭이 연결되어 있어야 한다. 앱/크롬 재시작에는 새 코드를 연결해야 하며 자동으로 제출 권한을 되살리지 않는다. Worklead의 중지나 확장의 자동 지원 탭 중지로 새로운 작업을 막는다. 이미 제출된 지원을 취소하는 버튼은 아니다. 수면/배경 탭/브라우저 정책으로 반응이 늦어질 수 있다. 30초 크롬 알람을 보완 수단으로 쓰며 절전 중 장치를 깨우지 않는다.

같은 연결에서 허가/완료 응답이 유실되거나 확장 작업만 다시 시작되면, 기존 공고의 완료 표시를 최대 3회 자동 대조한다. 확인되면 ‘공식 완료 표시를 재대조함 · 재제출 없음’으로 기록한다. 지원 버튼을 다시 누르지 않으며 계정 변경·로그인 만료는 연결을 해제한다. 자세한 경계는 [자동 복구 마일스톤](JOB_AUTO_APPLY_RECOVERY.md)을 따른다.

실행부는 미읽음 감시와 별도 포트·연결키를 사용한다. 본문/쿠키/세션/비공개 API를 추출하지 않는다. 계정 표식과 소개 내용은 확장 내부에서 해시로만 비교하며 본문·계정명·연결 비밀을 DB/로그에 쓰지 않는다. 계정 표식은 화면의 프로필 메뉴/이미지를 기반으로 하므로 서버 계정 ID를 확인한 증거가 아니다.

## 탐색 간격과 부하

당근은 5분마다 확인 시각이 된 지역만 점검한다. 최근 신규 제작 후보가 관찰된 지역 최대 8개를 10분 우선 확인하고, 일반 지역은 30분·그 외 C 지역은 120분 이상 간격을 둔다. 같은 글의 재등장을 성과로 중복 집계하지 않는다. 6초 요청 간격·하루 5,500회·429/차단 시 대기를 유지한다. 우선순위가 회전해도 최근 10분 우선 조회 8회 공유 한도를 지킨다.

정상 완료한 당근 탐색의 5분은 직전 시작 시각 기준 다음 점검 설정이다. 진행 중 중복 작업은 만들지 않으며 실패/부분 완료는 기존 종료 후 대기를 유지한다. 첫 동기화·서버 지연·수집량 때문에 실제 간격은 더 길 수 있다. 모든 지역을 5분마다 전수 조회하거나 누구보다 먼저 발견함을 보장하지 않는다. UI 자동 반영 지연, 공개 목록 유입 지연, 실제 게시→발견 지연, 제출 확인까지의 지연을 구분해야 한다. 현재 누락 경로와 다음 과제는 [전국 의뢰 감사](NATIONWIDE_OPPORTUNITY_AUDIT_20261025.md)를 따른다.

## 검증 구분

합성 DOM과 실제 로컬 HTTP에서 50점 경계·두 단계 클릭·기본 소개 선택·추가 질문·계정/소개/공고 변경·허가 만료·중복·응답 유실·DB 복원·일일 상한을 검사한다. 패키지·설치 DB 무결성과 실제 크롬에서 제출 성공한 증거는 별개다. 현재 설치/테스트 결과와 실제 연결·제출의 확인 여부는 [STATUS](STATUS.md)를 따른다.

기술 근거: [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), [alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms).
