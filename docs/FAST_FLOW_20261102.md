# 자동 탐색·지원 대기 시간 개선 (2026-11-02)

기존에 등록된 자동 지원을 추가 설정 없이 재개하면서, 발견부터 지원 검사까지 프로그램 내부에서 발생하는 불필요한 대기를 줄였다.

- 당근알바 수집을 별도 작업 스레드로 분리했다. 다른 사이트의 긴 수집이 당근 수집을 막지 않는다. 같은 소스의 수집은 중복 실행하지 않는다.
- 공고 저장 후 이벤트가 발생하면 자동 지원의 고정 5초 대기를 건너뛴다. 유휴 상태에서는 최대 0.25초 단위로 브라우저 이벤트와 새 신호를 확인한다. 처리 중인 지원이나 사이트 응답 시간을 포함하는 제출 시간 보장은 아니다.
- 스케줄러는 다음 예정 시각에 맞춰 깨어나며, 기존 60초 확인 간격 때문에 생기는 추가 지연을 줄인다. 소스별 재탐색 간격·요청 제한·일일 예산·일시 중지는 그대로 준수한다.

검증 및 설치 증거는 `artifacts/install-20261102-fast-flow`에 보관했다.

- 배포 소스 기준 관련 회귀 검사 99개 통과, 실패·오류·건너뜀 없음 (`final-focused.xml`).
- 패키지 기동·상태 계약·종료·시스템 Edge 검사 통과 (`package-probe.json`).
- 설치 프로그램 종료 코드 0. 설치된 백엔드 SHA256: `a78031841811d2d824c03d3551c2834a3696486b3d085e81e0c39ef1af92b4b5`.
- 앱 시작 전 32개 테이블을 비교해 모든 데이터가 동일함을 확인했다. 기존 공고 2,021건, SQLite 무결성 정상 (`installed-verification.json`). 재시작 후 새 공고를 수집해 2,022건으로 증가했다.
- 실제 앱에서 “자동 연결됨 · 대상 공고 대기”, 최소 점수 50, 하루 상한 20, 최근 자동 지원 창 응답을 확인했다. 로그인 계정 연결과 자동 실행 등록이 유지되었다. 자기소개 연결은 지원 양식 확인 시 이루어지며, 이번 확인 시점에는 아직 연결 전이었다.
- 현재 신규 제출 완료는 0건이다. 기존 지원 3건과 오래된 원문 보류 1건이 유지되었다. 실제 신규 제출 성공이나 게시부터 제출까지 시간 단축은 아직 측정되지 않았다.
- 운영 로그에서 `collector-daangn`의 요청 진행을 확인했다. 네트워크 오류 1회가 있었고 다음 요청들은 다시 성공했다.

사이트 공개 목록 반영, 지역별 재방문 간격, 앱 중단 시간의 영향을 받는다. 전국의 모든 새 공고를 즉시 발견하거나 다른 지원자보다 항상 먼저 제출한다는 보장은 하지 않는다. 기존 게시→발견 통계는 이 요인들을 포함하므로 프로그램 내부 처리 시간으로 해석하지 않는다.

이번 배포에는 작업 중이던 별도 M4 분류·어댑터 변경을 포함하지 않았다. 설치 전 실행 파일과 데이터 백업은 같은 증거 폴더의 `before-cutover`에 보존했다.
