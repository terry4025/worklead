# 메시지 자동 재연결과 연결 오류 해결 (0.5.0)

> 현재 확장은 **0.6.1**이며 [연결 복구·전국 발견 개선 진행](AUTOMATION_M4_PROGRESS_20261027.md)을 추가했다. 아래 메시지 허가/재연결 방식은 유지한다. 이미 저장한 연결은 재사용하고, Chrome에 실행 중인 확장은 새 버전으로 새로고침해야 한다.

메시지 감시와 자동 지원은 **별도 코드·탭·저장 허가**를 사용한다. 자동 지원만 연결했다고 메시지 감시가 연결되지는 않는다. 이 문서는 과거 0.1–0.4의 메시지 연결 수명 설명을 대체한다. 실제 설치·연결·수신 여부는 [STATUS](STATUS.md)의 최신 증거를 기준으로 한다.

## 이미 설치한 사용자의 연결 순서

1. 크롬 슬롯 1의 확장 관리 화면에서 **Worklead 당근 연결**을 새로고침하고 버전 **0.6.1**인지 확인한다. 설치 폴더는 `C:\Users\Administrator\AppData\Local\Worklead\chrome-message-extension`이다. 파일 업데이트만으로 Chrome에 실행 중인 이전 버전이 새로고침됐다고 판단하지 않는다.
2. Worklead의 **지원 준비·메시지 → 현재 크롬으로 연결**을 누른다. **메시지 감시도 다음 실행부터 자동 연결**은 기본으로 켜져 있다. **메시지 연결코드 복사**를 누른다.
3. 로그인한 당근알바 탭에서 확장을 열고 **위쪽 ‘메시지 표시 감시’** 입력란에 코드를 붙여 넣고 연결한다. 보이는 채팅 내용까지 표시하려면 앱과 확장의 선택 항목을 모두 켠다.
4. 실제 로그인·미읽음 관찰 응답을 확인한 경우에만 연결 성공으로 표시한다. Worklead에서 **미읽음 표시 감시 중**과 최근 관찰 시각을 확인한다. ‘연결 복구 중’은 아직 성공이 아니다.

자동 지원은 **아래쪽 ‘50점 이상 자동 지원’**에 **자동 지원 전용 연결 코드**를 넣고 별도 당근 탭에서 연결한다. 코드를 채팅이나 외부 문서에 보내지 않는다. Chrome 최초 설치·사이트/로컬 연결 권한·로그인은 사용자가 정상 화면에서 확인한다. 이미 부여한 권한은 다시 요구하지 않는다.

## 실패 메시지에 따른 조치

| 표시 | 의미와 조치 |
| --- | --- |
| 코드 종류가 다름 | 메시지 코드는 위쪽, 자동 지원 코드는 아래쪽에 넣는다. 새 코드는 목적·버전을 포함한다. 기존 두 필드 코드도 검증하며, 잘못된 목적은 서버 응답으로도 확인한다. |
| 코드 만료·연결 해제 | 임시 연결의 앱 재시작, 이전 코드, 저장 허가 폐기가 원인일 수 있다. 앱에서 해당 연결을 다시 준비해 새 코드를 복사한다. 저장 연결이 이미 성립했다면 ‘저장한 연결 재개’를 사용한다. |
| Worklead 연결 불가 | 앱 실행과 연결 준비 상태를 확인한다. 다른 Worklead 실행이 고정 포트를 사용 중이면 앱에 포트 오류가 표시된다. |
| 권한 필요 | Chrome이 표시하는 당근 사이트와 이 PC의 로컬 연결 권한을 확인한다. |
| 계정 화면 준비 안 됨 | 당근 탭 로딩 뒤 다시 연결한다. 빈 화면을 로그아웃으로 단정해 저장 허가를 지우지 않는다. |
| 로그인·계정 변경 | 처음 승인한 계정으로 직접 로그인 후 재개한다. 다른 계정으로 조용히 감시/지원을 계속하지 않는다. |
| 별도 탭 필요 | 메시지 감시와 자동 지원에 서로 다른 당근 탭을 선택한다. |

실패 이유는 팝업의 주기적인 상태 갱신에 덮이지 않는다. 잘못된 새 코드를 입력해도 기존 저장 허가를 먼저 삭제하지 않는다. 사용자 환경에서 발생했던 단일 원인이 확정된 것은 아니며, 만료 코드·잘못된 목적·앱 미실행·권한 거부를 재현 검사하고 구분하도록 보완했다.

## 재시작·중지·연결 해제

최초 연결 후 같은 계정으로 Worklead·Chrome이 다시 실행되면 저장한 메시지 허가로 새 실행 키를 받는다. Chrome이 다시 열렸고 이전 탭 ID가 사라진 경우 **비활성 전용 탭 하나**를 복구할 수 있다. 임의의 기존 당근 탭이나 대화방을 선택하지 않는다. 탭 새로고침 뒤에는 감시를 다시 주입한다. 일시 통신 실패는 최대 4분 간격까지 늘려 재시도한다.

같은 Worklead 실행 중 Chrome만 재시작해도 인증된 재연결마다 임시 키와 관찰 순서를 함께 바꾼다. 이전 미읽음 기준·공백 판단은 보존해 같은 수를 새 메시지로 중복 알림하지 않으며, 보이는 채팅 본문은 새 관찰 전까지 지운다. 이전 키로 본문을 읽고 있던 요청도 반영 직전에 다시 인증해 거부한다.

전용 탭을 직접 닫거나 다른 사이트로 이동·로그아웃·계정 변경한 경우 일시 중지한다. Worklead의 **감시 중지**는 다음 실행에도 유지하고, **저장한 메시지 연결 해제**는 메시지 허가를 폐기한다. 자동 지원 허가는 별도이며 메시지 연결 해제로 삭제하지 않는다. DB 복원은 저장 허가와 현재 실행 키를 폐기한다. 복원 과정의 저장소 삭제가 실패하면 DB 복원을 중단하고 현재 키도 정지한다.

자동 연결 기억을 끈 임시 연결은 앱 재시작 후 새 코드가 필요하다. 기존 0.4.0의 메시지 연결은 임시 연결이므로 업데이트 후 처음 한 번은 새 메시지 코드로 연결해야 한다.

## 읽는 정보와 저장 범위

- 기본 모드는 선택한 당근 탭의 로그인/화면 상태·미읽음 수·관찰 순서와 계정 일치 확인용 해시를 이 PC의 Worklead에 전달한다. 계정 해시는 화면에 보이는 프로필 메뉴 표식에서 계산하며 쿠키·세션·비공개 API를 읽지 않는다.
- 보이는 채팅 표시는 별도 선택 사항이다. 목록 패널은 열 수 있지만 대화방 선택·메시지 입력/전송·숨겨진 전체 대화 수집은 하지 않는다. 본문은 Worklead 메모리에만 두고 종료·계정 상실·연결 중지·관찰 만료 때 숨기거나 지운다. DB·파일·AI로 보내지 않는다.
- 메시지 장기 허가는 목적별 Windows 자격 증명 저장소와 Chrome의 신뢰 컨텍스트 전용 `storage.local`에 보관한다. 일반 DB·백업·화면 상태·로그에 넣지 않는다. 현재 실행 키는 `storage.session`에만 둔다. Windows 저장소가 불가하면 평문으로 우회하지 않는다.
- 재연결 수신부는 메시지 전용 `127.0.0.1:58348`이며 nonce/HMAC으로 양쪽을 확인한다. 장기 키 자체는 HTTP로 보내지 않는다. 매 실행의 임시 수신부는 Host·고정 확장 Origin·인증·형식·순서·크기를 검사한다. 자동 지원 수신부 `58347`과 허가를 공유하지 않는다.
- MV3의 `activeTab`, `scripting`, `storage`, `alarms` 및 사용자가 허용하는 사이트·로컬 접속 권한을 사용한다. 쿠키·debugger·webRequest 권한은 없다. [Chrome storage](https://developer.chrome.com/docs/extensions/reference/api/storage), [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), [service worker 수명](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)을 기준으로 한다.

## 알림의 의미와 남은 한계

첫 관찰은 기존 미읽음 기준값이다. 이후 미읽음 합계가 증가하면 앱 토스트/Windows 알림 큐에 연결하며 Windows 알림 선택·조용한 시간을 유지한다. 관찰 공백 뒤 증가했다면 ‘감시 재개 후 확인 필요’로 알리고 방금 수신된 메시지로 단정하지 않는다.

목표 읽기 주기는 2초다. 배경 탭·절전·Chrome 정책으로 늦어질 수 있고, 15초 이상 공백은 정상 감시로 표시하지 않는다. **합계가 같은 새 메시지, 감시하지 않은 대화방의 전체 본문, 감시가 꺼진 동안 읽고 사라진 메시지는 확보하지 못할 수 있다.** 자동 재연결 구현과 실제 수신 검증은 별도다. 모든 답장 감지를 완료한 것으로 기록하지 않는다.

## 검증

로컬 HTTP·Windows 격리 저장소·확장 worker/팝업 합성 환경·화면 계약·설치 실행 파일을 검사한다. 실제 Chrome 확장과 당근 서버를 연결한 결과, 실제 자동 지원 완료, 수신 답장 및 Windows 배너는 각각 별도로 검증해야 한다. 최신 검사 수와 설치 증거는 [STATUS](STATUS.md), 다음 운영 관문은 [마일스톤](AUTOMATION_MILESTONES_20261026.md)에 기록한다.
