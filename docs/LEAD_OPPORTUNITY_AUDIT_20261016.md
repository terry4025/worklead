## 이번에 구현한 동작

### 지원 준비

- 당근의 건당 제작 구매 의뢰 중 recommended/needs_review·모집 중·접근 가능·지원 전인 공고를 최신 게시순으로 모은다. 현재 규칙/프로필로 다시 평가하며 원문 소실·마감·대상 아님은 구분한다.

- 저장된 소개·기술을 초안에 그대로 사용하며 경력·성과·가격·포트폴리오를 만들지 않는다. 기존 초안과 사용자가 비운 초안은 자동 덮어쓰지 않는다. 편집 저장은 기존 텍스트와 비교해 충돌 시 거부한다.

### 메시지 표시 감시

- `지원 준비·메시지`에서 사용자가 시작하면 전용 Edge 프로필을 연다. 로그인은 사용자가 직접 한다. 카페·일반 Edge의 세션이나 쿠키를 복사하지 않는다.
- 인증 상태와 사이트의 정상 브라우저 저장소는 전용 Edge 프로필이 관리한다. Worklead가 세션을 DB로 추출하거나 메시지 내용을 별도 기록하는 기능은 없다. Edge 자체 저장소가 존재하지 않는다는 뜻은 아니다.
- 화면의 실제 채팅 버튼 접근성 이름을 **2초마다** 읽는다. 감시 자체가 페이지를 재조회하거나 채팅방을 열지 않으며 본문·발신자·연락처·계정 ID를 저장하지 않는다.
- 첫 관찰과 로그인 재연결은 기준값이다. 이후 미읽음 수가 증가하면 일반 문구로 앱 토스트와 기존 Windows 알림 큐에 연결한다. 종류 `daangn_message`, 설정 `notifications.daangn_messages`를 추가한다.
- 기존 Windows 알림 선택과 조용한 시간을 유지한다. 이 변경이 OS 알림 권한을 자동 허용하지 않는다. 처음부터/재시작 후 자동으로 로그인 창을 열거나 감시를 켜지 않는다.
- 미확인 표시는 0개와 다르다. 로그인 필요·표시 미인식·접근 제한·창 종료·오류를 감시 성공으로 표시하지 않는다. Worklead 또는 전용 Edge 종료 시 감시가 끝난다.
- **한계:** 미읽음 수가 그대로 유지된 새 메시지는 놓칠 수 있다. 메시지 단위 무손실 수신이나 2초 내 실제 도착 알림을 보장하지 않는다. 당근 자체 브라우저 알림은 사용자가 사이트에서 설정할 수 있지만 이번에 실제 수신을 검증하지 않았다.

## 검증

관련 백엔드 100개, 화면 전체 286개·TypeScript, Rust 알림 4개(선택 OS 검사 1개 제외), 모든 HTTP를 합성 응답한 실제 headless Edge의 로그인/0개/4개/미인식/중복 표시/창 종료 분기를 확인했다. 지원 초안 API는 동시 준비의 단일 생성·CAS 충돌·사용자 기록 보존·실제 제출 0회를 확인했다. 합성 화면 1440/900px 가로 넘침·JS 오류는 0이었다.

백엔드 전체는 1,098개 통과/선택적 자격 증명 1개 제외였다. 이후 복원 경합에서 감시가 영구 중단되던 문제를 고쳐 지원·메시지 관련 최종 38개와 계약·네이티브 관련 검사를 별도로 재검증했다. 복원 잠금 중 브라우저를 유지하고 기록을 보류하며, DB 접근 잠금을 얻은 뒤 generation을 비교해 다음 관찰을 새 기준값으로 삼는다. 이 집합들을 전체 검사 수에 더하지 않는다.

패키지·설치본과 실제 로그인 후 메시지 수신 결과는 최종 STATUS에 별도로 기록한다. 실계정 지원 제출·채팅 발송·카페 신규 게시·수주·수금은 이번 검증에 포함되지 않는다. 최신 패키지는 복사한 1,073건 DB에서 두 번 실행해 새 API·제출 거부·메시지 stopped/null·인증/Origin 거부·토큰 회전·정상 종료와 사용자 필드 보존을 확인했다.

최종 NSIS 업데이트와 앱 재실행을 완료했고 설치 DB 1,075건의 사용자 필드·설정·무결성을 보존했다. 카페 자동 수집에서 증가한 2건은 이번 지원 기능 성과가 아니다. 업데이트로 중단된 읽기 작업은 기존 수집 범위로 다시 시작했다. 실제 새 메시지 수신·OS 표시·지원 제출은 미검증이다. 설치 앱 `지원 준비·메시지 → 연결하고 감시 시작`에서 직접 로그인해야 한다. 감시 시작 전에는 연결 성공으로 표시하지 않는다.
