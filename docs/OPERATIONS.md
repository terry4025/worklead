# 운영·장애·백업 안내

## 당근 카페 (2026-10-13)

후속 오류 복구·작업 결과·게시 중단 개선까지 포함한 최신 설치본도 확인했다. 직전 두 실행 파일과 732건 DB의 온라인 백업은 `artifacts/cafe-followup-20261013/installed-before-final/`에 있다. 최종 빌드/설치 해시, 실제 네이티브 카페 화면·실행 기록, 기존 732건 사용자 입력·설정·동의 보존과 DB 무결성을 확인했다. 사용자가 취소한 컴퓨터 종료는 다시 예약하지 않는다. 다음 문단의 699→732건은 앞선 경로 B 설치 당시 이력이다.

경로 B 조정과 UI 개선을 포함한 최종 Windows 패키지와 설치본을 업데이트했다. 기존 두 실행 파일·699건 DB의 작업 직전 온라인 백업은 저장소의 `artifacts/daangn-cafe-b-20261013/installed-before-final/`에 있다. 설치 업데이트는 실행 파일 교체·해시 일치·정상 재실행·네이티브 카페 화면·정상 종료로 검증했으며 NSIS 마법사·새 계정 설치 검증과 구분한다. 기존 사용자 동의와 자동 게시 꺼짐을 보존했다. 기존 자동 수집이 재개되어 신규 33건, 총 732건이 됐으며 기존 699건 사용자 입력과 설정을 보존했다. 이벤트 보존 커서 전진은 사용자 설정 변경과 구분했다. 기능 동의가 당근의 자동화 허가나 카페의 홍보 게시 허용 근거를 대신하지 않는다.

개발용 frozen 브라우저 점검은 `worklead-backend.exe --cafe-browser-self-check --data-dir <별도 점검 폴더>`로 실행한다. 무작위 하위 프로필에서 합성 화면·쿠키만 사용하고 운영 DB나 로그인 프로필은 열지 않는다. 시스템 Edge 실행·영속성·기본 템플릿 자산만 확인하며 실제 사이트 로그인/게시 성공을 증명하지 않는다.

카페 작업 공간에서 위험 안내 확인 기록을 남긴 후 `세션 확인`을 실행한다. 로그인되어 있지 않을 때만 `브라우저 열어 로그인`을 누르고 전용 Edge 창에서 직접 인증한다. 앱은 비밀번호·인증번호를 입력하거나 저장하지 않는다. 인증·CAPTCHA·약관·차단 상태는 `needs_user`로 저장하고 카페 작업 전체를 정지한다. 직접 해결한 다음 로그인 동작으로 재확인한다. 자동 가입·회피·비공개 API 직접 호출은 하지 않는다.

프로필은 기본 설치의 `%LOCALAPPDATA%\Worklead\cafe-browser`에 있다. 다른 데이터 폴더로 실행하면 그 폴더의 `cafe-browser`를 사용한다. 쿠키가 있으므로 공유·진단 ZIP·DB 백업에 포함하지 않는다. 로그아웃/프로필 초기화가 필요하면 Worklead와 전용 Edge가 완전히 종료된 것을 확인한 뒤 이 정확한 폴더만 삭제하고 다시 직접 로그인한다. 일반 Chrome/Edge 프로필은 삭제하지 않는다.

페이지 이동은 한 큐에서 최소 8초 간격, 기본 하루 300회이며 KST 날짜로 집계한다. 게시 예산은 전송 시도 전에 보수적으로 차감한다. 기본 5회/일·30분 간격이다. 재시작·복원으로 이미 사용한 당일 예산을 되돌리지 않는다. 복원은 예약 게시를 끄고 대기 작업을 취소하며 세션을 다시 확인하게 한다. 게시 결과가 불확실하거나 내용이 다르면 원문과 내 글을 직접 대조해야 하며 자동 수정·재전송하지 않는다. 확인된 삭제·숨김 글은 재게시하지 않는다.

2026-10-13 경로 B 조정 승인으로 수집·게시·댓글의 기존 웹 경로 차단을 변경했다. 리드 수집에서 현재 템플릿 제목 또는 `seyj.kr` 링크가 있는 글과 기존 게시 URL을 제외한다. 다른 작성자의 같은 글도 제외될 수 있고 과거 다른 제목/링크의 내 글을 놓칠 수 있다. 상대 시각으로 최근 30일을 추정하며 원문 시각을 함께 기록한다. 표시 날짜가 없는 글을 최근 글로 추측하지 않는다.

게시는 DB 기존 기록을 먼저 검사하고 카페 홈·승인 게시판 목록의 같은 제목을 작성자 확인 없이 건너뛴다. 사용자 수동 기존 글 확인은 없다. 가입·게시 허용 근거·카페/게시판 승인과 기본 자동 게시 꺼짐, 한도·간격은 유지한다. 목록 구조를 읽지 못하거나 이전 제출 결과가 불확실하면 제출/재시도하지 않는다. 같은 제목의 타인 글을 내 글로 간주해 댓글을 감시하지 않는다.

게시 준비 중에는 자동 게시 체크를 끄거나 카페/게시판 승인을 취소할 수 있다. 예약 게시의 자동 게시 설정은 시작 전과 제출 직전에, 승인은 제출 직전에 다시 검사한다. 수동 ‘지금 게시’는 자동 게시가 꺼져 있어도 승인 조건을 만족하면 실행한다. 이미 제출된 글을 지우거나 수정하지 않는다. 최근 작업 안내와 실행 기록에서 실제 수집 건수·같은 제목 건너뜀·중단 이유를 확인한다. 조회 실패에는 해당 영역의 다시 불러오기를 사용하며, 실패를 실제 빈 결과로 간주하지 않는다.

댓글은 웹에 보이는 댓글과 펼칠 수 있는 답글만 읽는다. 문의 화면은 글별 표시 총 댓글 수·읽은 수·확인 시각을 보여주며 총수가 더 많거나 미확인일 때 `앱에서 전체 확인 필요`를 안내한다. 해당 안내가 없어도 미표시/삭제/숨김 댓글 전체를 읽었다는 보장은 아니다. 문의 분류는 규칙 기반이며 AI 보조 분류는 구현하지 않았다. 답글 초안은 화면에서만 제공한다. `리드로 만들기`는 기존 수동 입력 소스에 연결하며 외부 발송은 하지 않는다. 알림은 기존 새 추천 알림 설정·조용한 시간을 따르며 닉네임·원문·URL을 포함하지 않는다.

## 실행 파일 빌드

설치본 교체용 실행 파일은 `desktop`에서 `npm run tauri build -- --no-bundle`로 만든다. 전체 설치 프로그램은 `scripts/build-windows.ps1`을 사용한다. 배포 옵션 없이 `cargo build --release`로 만든 파일은 개발 서버 주소를 참조하므로 빌드 단계에서 거부한다. 교체 후 백엔드 준비 로그와 실제 앱 화면을 모두 확인한다.

## 실전 테스트에서 볼 항목

1. 수집 → 소스·범위에서 자동 수집 체크, 다음 자동 탐색 시각, 최근 탐색의 신규·중복·실패 수를 확인한다. 기본 창 닫기는 완전 종료다. 설정에서 트레이 숨김을 켜면 창을 닫아도 앱과 수집은 실행된다.
2. 실행 기록은 기본으로 전국 탐색·자동 재확인을 표시한다. 개별 확인·재분석·수동 입력·내보내기는 기록 종류를 전체로 바꿔 확인한다.
3. `부분 완료`이면 요청 실패와 해석 실패를 구분한다. 일부 공고의 404는 전체 수집 불능이나 모집 마감의 증거가 아니다.
4. 연결이 복구되면 소스·작업·건수·열린 상세를 다시 조회한다. 읽던 목록은 `목록에 반영 (F5)`으로 갱신한다.
5. 일주일 가속 테스트는 예약·중복·복구 검증이다. 실제 절전·네트워크 변경·장시간 실행 안정성은 실제 운용으로 따로 관찰한다.

개발 검증용 입력·메모·내보내기는 원본 DB의 복사본에서 수행하며, 설치된 사용자 DB에 합성 리드를 넣지 않는다.

## 데이터 위치 (Windows)

데이터: `%LOCALAPPDATA%\Worklead\`. 새 설치의 실행 파일은 `%LOCALAPPDATA%\Programs\Worklead\`에 둔다. 기존 설치의 실행 경로는 업데이트 시 유지하며 데이터를 자동 이동하지 않는다. 과거 설치에는 실행 파일과 데이터가 `Worklead` 폴더에 함께 있을 수 있다.

| 경로 | 내용 |
| --- | --- |
| `worklead.sqlite3` (+ `-wal`, `-shm`) | 운영 DB (WAL) |
| `worklead-demo.sqlite3` | `--demo` 실행 전용 DB (운영과 분리) |
| `logs\backend.log*` | 5MB × 5 회전. 토큰·Bearer·전화번호·이메일·주민번호 마스킹. 예외 메시지/원문 코드/절대 경로는 기록하지 않음 |

| `exports\` | CSV·JSON·진단 zip |
| `backend.lock` | 이중 실행 방지 잠금 |

## 시작 순서와 실패

셸 → sidecar 실행 → 잠금 → 마이그레이션(기존 DB 는 먼저 온라인 백업, 실패 시 되돌림) → 워커 시작 → 서버 시작 → 준비 줄 → 화면 연결.

| 증상 | 원인·조치 |
| --- | --- |
| "로컬 서비스에 연결할 수 없습니다" | 화면의 "서비스 다시 시작". 반복되면 `logs\backend.log` 확인 |
| `already_running` | 같은 데이터 폴더를 쓰는 백엔드가 이미 있음 (다른 창·이전 프로세스). 작업 관리자에서 `worklead-backend` 종료 |
| 재시작 한도 초과 | 앱 실행 기간의 자동 재시작 3회를 소진. 로그 확인 후 명시적 서비스 재시작 또는 앱 재실행 |
| 마이그레이션 실패 | 기존 DB 는 자동 백업에서 복구됨. 로그와 `backups\*-pre-migrate-*` 확인 |

## 수집 장애

| 상황 | 동작 | 사용자 조치 |
| --- | --- | --- |
| 401/403/CAPTCHA/차단 페이지/robots 금지 | 소스 정지, 알림, 기존 리드 상태 유지 | 원인 확인. 정책상 허용·접근 정상이 확인되면 "정지 해제". 우회하지 않는다 |
| 429 | 이번 실행 부분 완료, Retry-After 까지 예약 보류 | 기다림 (필요하면 예산·주기를 낮춤) |
| 예산 소진 | 이번 실행 중단, 다음 날 이어서 | 예산 조정 (정책 범위 내) |
| 파싱 실패 증가 | 사이트 구조 변경 가능성. 정상 0건으로 기록하지 않음 | 조사 프로필 재확인 |
| 네트워크·5xx | 같은 실행에서 재시도 없음, 다음 실행에서 처리 | — |
| AI 실패·비용 상한 | `failed`/`rules_only`, 규칙 결과 유지, 자동 재요청 없음 | 상태·상한 확인. 같은 입력의 재분석은 기존 AI 캐시를 사용하며 유료 요청을 다시 보내지 않음 |

robots.txt 요청에도 차단/요청 제한 처리를 적용한다. 401/403/CAPTCHA는 소스를 정지하며, 429는 Retry-After까지 기다린다. robots의 5xx·네트워크 확인 실패는 5분 유예한 후 새 실행에서 다시 확인할 수 있다. 상세의 오류·유예와 모집 마감은 구분한다.

로컬 서비스가 실행 중 끊기면 상단의 `서비스 다시 시작`으로 복구할 수 있다. 자동 재시작은 앱 실행 기간에 최대 3회이며 준비 완료만으로 횟수를 초기화하지 않는다. 명시적인 서비스 재시작은 새 3회 예산을 시작한다. 버튼은 준비 완료까지 기다리고 겹친 클릭은 한 번만 처리한다. 계속 실패하면 앱을 완전히 종료하고 로그 폴더를 확인한다.

스케줄은 앱이 켜져 있을 때만 동작한다. 절전·종료 중 놓친 구간은 재개 후 1회만 보충한다.

## 데스크톱 설정

설정 → 데스크톱에서 선택하며 변경 즉시 이 PC에 적용된다. 트레이 숨김·Windows 알림·Windows 로그인 시 자동 시작은 기본 꺼짐이다.

- 트레이 숨김: 창 닫기를 숨김으로 바꾼다. 트레이 메뉴에서 열기·숨기기·완전 종료할 수 있다. 트레이 생성에 실패하면 창 닫기는 완전 종료하며 숨김 옵션을 사용할 수 없다. 앱을 다시 실행하면 숨겨진 기존 창을 연다.
- 자동 시작: 현재 실행 파일의 따옴표 경로와 `--autostart`를 Windows 사용자 로그인 항목에 등록한다. 트레이 숨김도 켰을 때만 숨겨서 시작한다. 다른 경로의 등록이나 Windows 승인 상태를 읽지 못하면 오류를 표시하며 덮어쓰지 않는다. 같은 설치의 업데이트는 등록을 유지하고 제거는 해당 설치 경로의 등록만 정리한다.
- Windows 알림: 새 추천·의미 있는 변경·소스 장애 중 설정에서 선택한 종류를 네이티브 셸이 처리한다. 숨긴 창에서도 동작하고 조용한 시간·현재 옵션을 전송 직전에 재확인한다. 켜기 전 이벤트와 24시간 지난 이벤트는 보내지 않는다. OS에는 공고 제목·연락처 대신 고정 문구만 전달한다.
- 알림 전송 시도를 먼저 디스크에 기록한다. 중단돼 결과가 미확인인 시도는 자동으로 다시 보내지 않는다. 중복 방지와 함께 중단 구간의 알림 누락 가능성이 있다. Windows 요청 수락은 실제 배너 표시·클릭을 보장하지 않는다. Windows 방해 금지·알림 설정도 영향을 준다.

## 백업·복원

- 백업: SQLite 온라인 백업 API 로 WAL 까지 일관되게 복사하고 `PRAGMA integrity_check` 로 확인한다 (DB 파일 단순 복사가 아님). 코드: `worklead/storage.py: backup_database`.
- 설정 → 백업·복원 → `지금 백업 만들기`. 백업 목록에서 선택하면 필수 스키마·외래키·JSON·버전·무결성과 파일 해시를 검사한다. 전체 파일명과 리드 수를 확인하고 복원 동의 후 실행한다. 데모 파일과 운영 파일은 분리한다.
- 복원: 새 작업과 DB 접근 보류 → 진행 중 접근 종료 대기(10초 내 끝나지 않으면 변경 없이 재시도 안내) → 별도 복사본 검증·필요한 마이그레이션 → 현재 DB 안전 백업 → 검증된 파일 교체. 실패하면 안전 백업으로 되돌린다. 현재 DB 자체가 손상돼 안전 백업 생성도 불가능한 경우에는 유효한 기존 백업을 이용한 오프라인 복구가 필요하다.
- 메모·영업 기록·설정은 백업 시점으로 돌아간다. 대기·진행 작업은 취소하고 자동 수집과 AI를 끈다. AI 전송 동의·요금 확인도 해제한다. 오늘 이미 쓴 수집 요청 사용량·현재 요청 상한, 별도 AI 비용 기록과 Windows 키는 유지한다. 필요한 설정을 확인하고 직접 다시 켠다.
- 복원 후 화면의 목록·상세·설정·실행 기록을 다시 조회하며, 복원 전 응답이 늦게 도착해도 캐시를 덮지 않는다. 응답 유실 시에는 복원 결과가 미확인이라고 표시한다. 먼저 화면 데이터만 다시 불러오며, 새 복원에는 재검증과 재동의가 필요하다.
- `backups\`에는 수집 원문·사용자 기록도 포함될 수 있다. 백업 파일은 자동 삭제하지 않는다. 백업을 다른 곳에 보관할 때는 온라인 백업으로 생성된 `.sqlite3` 파일을 사용한다. 손상·미지원 버전·별도 WAL에 의존하는 파일은 거부한다.
- 화면의 DB 백업·복원은 `desktop-settings.json`과 `native-notifications.json`을 교체하지 않는다. DB를 이전 시점으로 복원해도 알림 시도 기록을 유지해 같은 알림을 다시 보내지 않는다. PC 데이터를 통째로 이전할 때는 앱을 완전히 종료한 뒤 DB 백업과 두 파일을 함께 보관한다. 두 파일을 없애면 PC 설정과 중복 방지 기록을 잃는다.

## 보존·삭제

- 수집 원문 본문: 기본 30일 후 삭제 (설정 가능). 관심·진행 중 리드는 유지.
- 메모·영업 기록: 사용자가 지우기 전까지 유지.
- 일반 제거는 데이터와 Windows AI 키를 유지한다. 제거 화면의 `데이터도 삭제`를 선택한 뒤 확인하면 현재 사용자의 `%LOCALAPPDATA%\Worklead`, `%LOCALAPPDATA%\app.worklead.desktop`, `%APPDATA%\app.worklead.desktop`에 있는 리드·메모·설정·로그·내보내기·백업·AI 비용 기록과 고정 Worklead 데이터 경로에 연결된 Windows AI 키도 삭제한다. 키 삭제 실패 시 프로그램 파일 제거를 중단한다. 별도 `WORKLEAD_DATA_DIR`와 그 경로의 키, 다른 위치에 복사한 파일은 유지한다. 저장장치의 복구 불가능한 소거는 보장하지 않는다.
- 무인 제거·업데이트는 데이터를 유지한다. 앱 또는 수집 서비스가 실행 중이면 강제 종료하지 않고 먼저 완전 종료하도록 안내한다. 연결 폴더·파일 잠금·경로 검사가 실패하면 삭제 전에 중단하며, 삭제 중 오류나 새 파일 발생은 일부 남음으로 보고한다.
- 제거 템플릿은 Tauri CLI 2.11.5 원본에 필요한 변경을 적용한 `desktop/src-tauri/installer-template.nsi`다. CLI를 업데이트할 때 새 원본과 비교하고 전체 템플릿/유지/삭제/업데이트 하네스를 재검증한다. 원본 버전·해시와 변경 근거는 `artifacts/privacy-relations-20260930/uninstall/metadata.json`에 보존했다.

## 진단 내보내기

수집 → 내보내기 → "진단 정보": 버전, 허용한 설정 상태/숫자 집계, 소스 상태/오류 코드, 최근 실행 50건의 집계와 알려진 로그 이벤트의 통계를 zip으로 저장한다. 공고·메모·프로필·검색어 원문, 파일 경로, 토큰, 예외 메시지와 원본 로그는 복사하지 않는다. 식별자는 내보내기마다 별칭을 사용하며 로그는 각 파일의 마지막 256KiB까지만 통계로 변환한다.

CSV/JSON 리드 내보내기와 DB 백업은 사용자가 저장한 원문과 기록을 포함하므로 진단 파일과 내용이 다르다. 진단 파일은 취소·실패 시 부분 파일을 남기지 않으며 같은 초에 만든 파일도 각각 보존한다.

## 유사 공고 관계

상세의 관련 글에서 `관계 확인`, `연결 해제`, `다시 연결 확인`을 선택한다. 양쪽 글의 관계 표시만 바뀌며 리드·원문·메모·영업 상태·계약은 합치지 않는다. 해제 판단은 재수집 후에도 유지한다.

응답이 유실되거나 다른 창에서 먼저 변경했으면 `현재 관계 불러오기`로 상태를 읽은 뒤 다시 선택한다. 불확실한 변경은 자동 재시도하지 않는다. 복원·서비스 재시작 전에 읽은 관계로 변경하면 거부하고 최신 상태를 조회하도록 안내한다.

## 선택 AI 분석

설정 → AI 분석에서 현재 지원하는 OpenAI/GPT-4.1 mini 스냅샷을 설정한다. 기본은 꺼짐이며 규칙 필터는 키 없이 작동한다. 키 저장·설정 저장은 유료 요청을 보내지 않는다. 키는 현재 Windows 사용자의 자격 증명 저장소에 별도로 저장하며 DB·백업·진단·내보내기에는 넣지 않는다. 키 교체·삭제는 AI를 끈다. 실제 API 연결 성공과 설정 준비 상태를 구분한다.

전송 동의·공식 표준 요금 확인·사용자 환산값·양수 일/월 상한을 확인하고 저장한 후 AI를 켤 수 있다. 환산값 변경은 요금 확인과 AI 사용을 해제하며 저장한 요금 버전이 현재 버전과 다르면 다시 확인해야 한다. 상한 미설정·0원, 읽을 수 없는 키/비용 기록은 전송을 중지한다. 요금 확인일과 근거는 화면에 표시한다. 비용은 공개 요금과 입력한 환산값에 따른 추정이며 실제 계정 청구서·세금·수수료나 다른 앱의 사용량을 포함하지 않는다.

규칙에서 개발 관련 건당 지급 후보로 남은 글만 AI를 검토한다. 시급·일급·주급·월급·연봉·관련 없는 글은 AI 요청에서도 제외한다. 마스킹한 제목·본문·규칙 업무 분류·원문 첫 문장 기반 규칙 요약을 보내며 내 조건·보유 기술·메모·영업 기록은 보내지 않는다. 알려진 연락처·비밀 표식을 가리지만 모든 이름과 주소 제거를 보장하지 않는다. `store:false` 요청은 제공자의 모든 보관이 없다는 보장을 뜻하지 않는다.

원문 DB 저장을 끝낸 뒤 별도 파일에 비용을 예약하고 한 번만 HTTPS로 요청한다. 요청 전 예약을 영속 저장하며 응답 유실·중단·모델/요금 계층 미확인은 예약 금액을 미확인 비용으로 유지한다. 일/월 집계는 한국 시간 기준이며 사용 추정·예약·미확인 금액을 합쳐 상한을 검사한다. 다른 달/날짜로 넘어가도 같은 입력의 미확인 요청은 자동 재전송하지 않는다. 키 교체·상한 변경·동의 재설정·DB 복원으로 이 기록을 초기화하지 않는다.

캐시는 원문·모델·규칙·프로필·사용자 확인이 같은 입력에서 재사용한다. AI 결과의 짧은 원문 인용이나 요약은 캐시에 남을 수 있으나 전체 원문/프로필/키는 별도 비용 파일에 저장하지 않는다. 기본 DB 백업에는 이 파일을 포함하지 않으므로 PC 이전 시 앱을 완전히 종료한 뒤 따로 보관하며, 새 PC의 키는 설정 화면에서 다시 입력한다.

AI는 요약·원문 근거·불확실성·확인 질문·의도 제안만 보완한다. 추천·점수·보수·마감·재택·적격성은 규칙 결과를 유지한다. 응답 중 입력·설정·사용자 확인·복원 세대가 바뀌면 오래된 결과를 적용하지 않는다. 장애나 비용 상한에서도 원문과 규칙 결과는 조회할 수 있다.
