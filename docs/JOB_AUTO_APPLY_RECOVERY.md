# 자동 지원 복구 마일스톤 (2026-10-25)

사용자의 ‘완전 자동화를 위한 다음 마일스톤’ 요청에 따라, 같은 Worklead·Chrome 연결에서 응답 유실과 확장 작업 중단을 복구한다. 기존 50점 정책과 추가 질문 보류를 유지한다. 전체 앱·Chrome 재시작 후 무인 재연결은 이번 범위에 포함하지 않는다.

## 해결한 병목

이전에는 제출 15초 뒤 lease가 만료되면 결과를 계속 미확인으로 남겼다. 확장 작업이 다시 실행돼도 시도 ID만 남아 있어 원래 공고·계정·소개를 대조할 수 없었다. 최종 버튼은 이미 눌렸을 수 있으므로 새 제출 허가나 재클릭으로 해결할 수 없다.

## 현재 동작

1. 지원 양식을 검토한 뒤, 서버가 **완료 대조 전용 토큰**을 반환한다. 제출 허가와 다른 임의 값이며 해당 시도·계정·소개·현재 연결에 묶인다. 서버 메모리에서 15분만 유효하다.
2. 확장은 제출 허가를 요청하기 **전**에 토큰·공고·해시·단계를 `chrome.storage.session`에 기록한다. 자기소개 원문·계정명·쿠키·비공개 API는 저장하지 않는다.
3. 허가 응답 유실, 최종 클릭 뒤 확장 작업 중단, 완료 응답 유실이면 같은 전용 탭에서 공식 ‘지원 취소’ 표시를 최대 3회 읽는다. 첫 대조는 허가 요청 준비 기록 시점의 5초 뒤부터 가능하며, 추가 대조는 15·30초 간격이다. 감시 알람/탭 정책으로 실제 간격은 길어질 수 있다. 대조 중 다른 공고가 같은 탭을 덮어쓰지 않는다.
4. 대조 경로는 `inspect`와 `/reconcile`만 사용한다. `open`, `submit`, `/permit`을 호출하지 않는다. 완료 표시가 없으면 결과 미확인을 유지하고 새 제출을 시도하지 않는다.
5. 서버는 원래 허가·별도 journal·계정·소개·세대·토큰 만료를 확인한 뒤에만 `submitting/uncertain → submitted`로 확정한다. 이미 확정된 대조 응답을 다시 받아도 활동·완료 알림을 추가하지 않는다. 오늘 예약 수는 제출 확인 수로 이동하며 총 사용량을 줄이지 않는다.
6. 로그인 필요나 다른 계정을 관측하면 `/pause`로 기존 토큰·lease를 폐기하고 연결을 해제한다. 원래 계정으로 돌아와도 새 연결이 필요하다. 중지·새 연결·DB 복원·앱 재시작·토큰 만료도 기존 복구 권한을 되살리지 않는다.

계정 해시 계산 중 화면이 바뀌면 완료 증거도 거부한다. 화면 읽기와 탭 이동은 단계별 8초 상한, 로컬 HTTP는 2.5초 상한을 둔다. 시간초과는 완료 증거가 아니다. 브라우저 호출 자체의 취소를 보장하지 않으므로 뒤늦은 실행도 기존 공고 대조·3초 허가·중복 방지 검사를 통과해야 한다.

과거 제출 사실 대조는 새로운 지원 자격 검사와 다르다. 제출 뒤 점수가 내려가거나 모집이 마감돼도 유효한 공식 완료 증거를 무시하지 않는다. 보수·점수 조건을 완화해 새로 지원하는 기능은 아니다.

## 설치와 남은 단계

확장 버전은 **0.2.1**, ID와 권한은 이전과 같다. Worklead 설치 폴더의 확장을 새로고침하고 [자동 지원 연결 안내](JOB_AUTO_APPLY.md)에 따라 연결한다. 기존 `chrome://extensions/` 도구 차단 경계는 유지하며, 파일 교체가 Chrome 설치·권한 확인·실제 연결 성공을 뜻하지 않는다.

`chrome.storage.session`은 확장 서비스 워커의 재기동을 견디지만 브라우저 재시작·확장 새로고침 시 사라진다. [Chrome Storage 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/storage)를 기준으로 설계했다. 새 키를 외부 페이지·일반 디스크·동기화 저장소에 노출해 이 경계를 우회하지 않는다.

다음 단계는 실제 선택 탭에서 최초 연결과 기본 소개 DOM·공식 지원 완료·미읽음 알림을 실증하는 것이다. 이후 명시적 상시 운영 설정과 재시작 재연결을 설계하고, 실제 게시→발견→제출 확인 지연 및 장시간 부하를 측정한다. 현재 구현만으로 무인 재시작·전국 최단 발견·채택/수익을 완료했다고 판단하지 않는다.

## 검증

관련 백엔드 회귀는 실제 loopback HTTP·SQLite·동시 요청으로 검사한다. 확장 검사는 실제 worker/content 소스로 worker 재시작·허가 유실·계정 변경·영구 지연·해시 계산 중 화면 변경을 재현한다. 시스템 Edge는 모든 요청을 합성 응답하며, 실제 Chrome 확장 실행이나 당근 제출 성공 증거와 구분한다. 최종 결과와 설치 검증은 [STATUS](STATUS.md) 및 `artifacts/auto-recovery-20261025/`에 기록한다.
