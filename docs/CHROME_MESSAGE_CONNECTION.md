# 로그인한 크롬으로 Worklead 메시지 표시 연결

2026-10-25 확장 0.2.0에 [별도 50점 자동 지원](JOB_AUTO_APPLY.md)이 추가됐다. 현재 이름은 **Worklead 당근 연결**이다. 이 문서의 메시지 연결은 계속 읽기 전용이며 자동 지원은 별도 코드·권한·탭으로 연결한다. 기존 확장 이름/7개 파일 기록은 0.1.0 검증 당시의 이력이다.

후속 0.2.1은 [제출 완료 자동 대조](JOB_AUTO_APPLY_RECOVERY.md)를 추가한다. 권한·ID·메시지 감시 범위는 동일하다. 같은 세션의 확장 작업 중단을 복구하며 전체 브라우저 재시작은 새 연결이 필요하다.

사용자가 지정한 크롬 슬롯 1의 로그인 상태를 그대로 사용한다. 기존 쿠키·프로필을 다른 브라우저로 복사하지 않는다. 아래 설치와 연결은 사용자가 확인한 뒤 진행하며, 파일을 준비하는 것만으로 확장을 설치하거나 권한을 부여하지 않는다.

## 무엇을 읽고 어디로 전달하는가

- 확장 팝업을 직접 실행한 **현재 당근알바 탭 한 곳**만 선택한다.
- 화면의 로그인 필요 여부와 채팅 버튼의 미읽음 수만 읽는다. 채팅방을 열거나 지원하기·제출·메시지 발송을 실행하지 않는다.
- 전달 내용은 `state`, `unread_count`, `sequence` 세 값뿐이다. 수신처는 **이 PC의 Worklead(127.0.0.1)**다.
- 본문·발신자·프로필·지원서·연락처·쿠키·브라우저 기록을 읽어 전달하지 않는다. 당근 비공개 API나 웹소켓을 직접 재현하지 않는다.

## 권한과 연결 수명

확장 Manifest V3의 `activeTab`, `scripting`, `storage`를 사용한다. 사용자 클릭으로 현재 탭을 읽는 임시 권한이며 전체 사이트의 상시 접근 권한은 선언하지 않는다. 로컬 수신에 필요한 `http://127.0.0.1/*`은 선택 권한으로, 연결 버튼을 누를 때 크롬이 확인한다. 쿠키·debugger·webRequest 권한은 없다. [Chrome activeTab 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [확장 네트워크 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests).

메인 앱 API 토큰을 확장에 주지 않는다. 매 연결마다 별도의 임시 256비트 연결 키와 임의 로컬 포트를 만들고, 정해진 확장 ID·Host·키·JSON 형태·512바이트 상한을 검사한다. 연결 키는 URL·상태 조회·로그·일반 DB·화면 텍스트·React Query 캐시에 넣지 않는다. 사용자가 복사한 코드는 확장 팝업으로만 전달하고 이후 입력란을 지운다. 크롬의 `storage.session`은 기본적으로 콘텐츠 스크립트에 노출되지 않는 메모리 저장소다. [Chrome storage 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/storage).

Worklead에서 다시 연결하면 이전 키를 폐기한다. 앱 종료·재시작에는 다시 연결해야 한다. 확장 중지·탭 종료·재탐색으로 샘플이 끊기면 앱에서 정상 감시로 표시하지 않는다. Edge와 크롬 감시를 동시에 켜지 않는다.

## 사용자 설치·연결 순서

2026-10-16 사용자가 설치·연결을 승인했다. 브라우저 도구는 보안 정책상 `chrome://extensions/`를 열 수 없으므로 아래 설치 화면은 직접 조작해야 한다. 승인 대기가 아니라 도구의 URL 제한이며, 권한을 우회해 설치하지 않는다.

1. Worklead의 **지원 준비·메시지 → 현재 크롬으로 연결**을 누른다. 이 단계는 이 PC에 확장 파일과 연결 코드를 준비하며 확장을 설치하지 않는다.
2. **확장 폴더 경로 복사**로 준비된 폴더를 확인한다. 현재 설치에서는 `C:\Users\Administrator\AppData\Local\Worklead\chrome-message-extension`이다.
3. 크롬 슬롯 1의 `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**로 해당 폴더를 선택한다. 확장 이름은 **Worklead 당근 메시지 연결**, ID는 `ljakiellilahkchbfjalkecollnfldoc`이다. 설치 권한은 사용자가 직접 확인한다.
4. 로그인된 당근알바 탭을 선택하고 Worklead 확장 팝업을 연다. Worklead에서 **크롬 연결코드 복사**를 누른 뒤 팝업에 붙여 넣고 **이 당근 탭 연결**을 누른다. 로컬 연결 권한을 직접 확인한다. 연결 코드를 채팅·웹페이지·외부 문서에 보내지 않는다.
5. Worklead에 **미읽음 표시 감시 중**과 실제 관찰 시간이 나타나는지 확인한다. 설치·연결 대기·미확인을 감시 성공으로 보지 않는다.

## 알림의 의미와 한계

첫 관찰은 기존 미읽음 기준값이므로 새 메시지로 알리지 않는다. 이후 카운터가 증가하면 기존 앱 토스트/Windows 알림 큐에 연결한다. 조용한 시간·Windows 알림 선택을 유지하고 권한을 자동 허용하지 않는다.

표시를 읽는 목표 주기는 2초다. 배경 탭·절전·브라우저 정책 때문에 실제 주기가 늦어질 수 있으며, 한동안 샘플이 없으면 연결 끊김으로 표시한다. 복귀 후 미읽음 수가 늘면 ‘감시 재개 후 확인 필요’로 알리며, 이를 방금 도착한 새 메시지로 단정하지 않는다. 로그인 소실·다른 화면·DB 복원에서는 새 기준을 사용한다. 미읽음 수가 그대로인 새 메시지와 감시가 꺼진 동안 읽고 지워진 메시지는 감지하지 못할 수 있다.

## 검증 상태

상태·미읽음·순서만 받는 실제 로컬 HTTP 검사, 확장 worker의 탭/프레임/출처 제한, 합성 DOM의 카운터·로그인·중복·재주입, 연결 키 회전/중지, 데이터 복원·heartbeat 공백과 초안 전용을 자동 테스트한다. 분리한 운영 DB 복사본에서 frozen API와 포함 확장 파일의 일치를 검사한다. 이는 실제 Chrome 확장 설치·새 메시지 수신·OS 표시 검증이 아니다. 최종 자동·설치·실사이트 증거는 `STATUS.md`에 구분해 기록한다.

현재 크롬 로그인 상태와 미읽음 0개 표시는 실사이트에서 이미 확인했다. 이번 연결 기능의 실제 수신 검증은 사용자 확장 설치/권한 확인 이후에 가능하다. 실제 지원 제출·채팅 송신은 하지 않는다.
