# EXAONE AI 보조 · 맞춤 자동 지원 · 수집 보강 설계 (2026-11-09)

## 1. 목표와 성공 기준

Worklead가 당근알바에서 재택·온라인 개발 일감을 더 많이 찾고, 공고마다 맞춤 문구로 자동 지원하며, 고객 응대 초안을 빠르게 쓰도록 돕는다.

성공 기준:
- 규칙이 놓친 실제 개발 의뢰(예: "C샵 자동매매 프로그램 오류 수정", "컴퓨터 홈페이지제작")가 확인 필요 또는 자동 지원 대상으로 올라온다.
- 자동 지원은 공고별 AI 문구를 그대로 제출하고, 포트폴리오 `https://www.seyj.kr/`가 항상 들어간다.
- 문구 검사를 통과하지 못하면 제출하지 않는다.
- 채팅 답장·견적서는 초안으로만 보여 준다.
- 수집이 앱·PC 공백 뒤에 놓친 글을 따라잡고, 구글시트·아두이노 같은 의뢰 제목을 걸러 내지 않는다.

## 2. 사용자 결정 (2026-11-09)

| 항목 | 결정 |
|---|---|
| AI 공급자 | LG EXAONE `k-exaone_v2.5` (무료 API). 1·2·3번 기능 모두 사용 |
| 응답 원칙 | `E:\프리랜서 뉴 던` 문서를 압축해 시스템 프롬프트로 사용 |
| 맞춤 지원 제출 | 승인 없이 완전 자동 |
| AI 문구 실패 시 | 보류 후 재시도, 끝내 실패하면 보류 + 알림 (기본 자기소개로 대체하지 않음) |
| 채팅 답장 | 초안만 보여 줌. 전송은 사용자 |
| AI가 다시 올린 공고 | 자동 지원 대상에 포함 (아래 엄격 조건) |
| 포트폴리오 | 모든 지원 문구에 항상 포함 |

알려 둔 제약 (사용자가 감수하기로 함):
- EXAONE 약관은 비상업적 이용만 허용한다.
- 결과물을 제3자에게 주기 전에 사전 검토하라는 조항이 있다. 완전 자동 제출은 이 조항과 충돌한다.
- 입력값은 학습 거부를 설정하기 전까지 학습에 쓰일 수 있다. 사용자는 EXAONE 플랫폼에서 학습 거부를 설정한다.
- `10_실행체크리스트_AI지침.md` E절 5항("초안만, 발송은 사용자")과도 다르다. 이번 결정이 우선한다.

## 3. 확인된 사실

- **API**: `POST https://api.exaone.ai/v1/chat/completions`, OpenAI 호환.
  - 시험 호출 결과: 합성 공고 1건, `reasoning_effort=low`에서 약 8.4초, 토큰 474개.
  - 한도 헤더: 초당 1회, 분당 60회, 하루 86,400회.
  - 응답 `content` 앞에 `\n\n`이 붙을 수 있다. 추론 과정은 `reasoning_content`로 따로 온다.
- **문구 지시 준수**: 원문 인용 지시를 일부 어기고 말을 바꿨다. 근거 검사를 코드로 한다.
- **당근 지원 폼**: 2026-11 번들 `apply-form-sidebar-*.js` 기준.
  - 지원 요청은 선택된 탭의 입력 내용을 그 지원의 `comment`로 보낸다.
  - 이력서 자기소개 목록을 저장하는 요청에는 기존 탭의 기준값(원래 내용)이 들어가고, 새로 추가한 탭만 새 항목으로 붙는다.
  - 따라서 "기본" 탭 칸을 바꿔 제출해도 저장된 "기본" 자기소개는 바뀌지 않는다. 첫 실제 제출 뒤 이력서 화면에서 다시 확인한다.
- **채팅 본문**: Chrome 확장 `chat-content.js`가 사용자가 연 채팅 패널의 보이는 텍스트만 백엔드 `ChatView`(메모리, 저장 안 함)로 보낸다. 전용 Edge 경로는 미읽음 배지만 본다. 채팅 초안은 Chrome 확장 연결과 "보이는 채팅 표시" 동의가 켜진 경우에만 동작한다.
- **수집 진단** (2026-11-09):
  - 앱이 켜져 있는 동안 99개 지역 모두 34분 이내(90%)에 재방문한다. 24시간 피드 확인 978회 중 누락 가능은 1회다.
  - 손실 원인은 세 가지다. 앱·PC 공백(최대 21시간), 제목 필터 누락(구글시트·아두이노 등), 의도가 애매한 의뢰를 규칙이 제외하는 것.
  - 당근 직종에는 IT 분류가 없고, 현재 피드가 보는 4개 직종이 맞다.

## 4. 구성 요소

### 4.1 EXAONE 공급자 — `backend/worklead/analysis/exaone_provider.py` (신규)

- 기존 `OpenAIProvider`와 같은 경계(트랜잭션 밖 실행, 응답 크기·시간 상한, 실패 코드)를 따른다. 전송은 OpenAI 호환 chat completions 형식이다.
- 공용 호출 함수: `complete(messages, schema, effort, max_tokens) -> (json, usage)`.
  - JSON 스키마 응답을 요청한다. 지원되지 않으면 `content`를 trim한 뒤 JSON으로 파싱하고 pydantic으로 검증한다.
  - `reasoning_content`는 저장·표시하지 않는다.
- **호출 간격**: 프로세스 전역 리미터로 호출 간격을 1.1초 이상 둔다.
  - 429를 받으면 `retry-after`(없으면 2초)만큼 기다렸다가 최대 2회 다시 시도한다.
  - 대기열 우선순위: 지원 문구 > 채팅 초안 > 견적서 > 경계 재검토 > 보조 분석.
- **키**: 기존 `services/credentials.py`의 Windows 자격 증명 저장소에 provider `exaone`으로 보관한다. 설정 화면에서 사용자가 직접 입력한다.
- **비용**: 무료이므로 금액 상한 대신 하루 호출 상한 `daily_call_cap`(기본 300)을 둔다. 원장(ledger)에는 비용 0, `cost_basis="free"`로 기록한다.
- **개인정보**: 보내기 전에 기존 `mask_personal`을 적용하고, 다음을 추가로 가린다.
  - 채팅 상대 표시 이름 → "고객"
  - 계좌번호 형태
  - 당근 주소 줄
  - 공고 원문의 URL은 이미 `[URL]`로 가려진다.

### 4.2 AI 설정 — 기존 `AiSettingsPanel.tsx`, `analysis/coordinator.py` 확장

- `provider`: `openai` | `exaone`. `exaone` 선택 시 `model="k-exaone_v2.5"`.
- 기능별 스위치를 둔다. 모두 기본 꺼짐이다.
  - `assist_review`: 보조 분석
  - `assist_recheck`: 경계 재검토
  - `assist_application`: 맞춤 지원 문구
  - `assist_chat`: 채팅 초안
  - `assist_quote`: 견적서
- 기존 `enabled` + `external_transfer_consent`가 모두 켜져야 외부 전송한다. 이 규칙은 그대로다.
- 프로필에 다음 항목을 추가한다(`services/settings.py` `DEFAULT_PROFILE`, 스키마, 설정 화면).
  - `portfolio_url`: 기본 `https://www.seyj.kr/`
  - `price_anchor_note`: 기준가 안내 문구. 선택 항목이고, 비어 있으면 금액을 말하지 않는다.

### 4.3 응답 원칙 프롬프트 — `backend/worklead/analysis/prompts.py` (신규)

- `PLAYBOOK_VERSION`과 압축 원칙(약 1,500자)을 코드 상수로 둔다. 런타임에 E: 드라이브를 읽지 않는다.
- 출처는 문서 01·03·04·10·11이다. 문서가 바뀌면 사람이 다시 압축하고 버전을 올린다.
- 담을 원칙:
  1. 만들어 주는 사람이 아니라 "무엇을 왜 만들지 알려 주고 일부를 실현하는" 컨설턴트로 쓴다.
  2. 약속 − 성과 = 사기. 10% 낮춰 말하고, 안 해 본 것은 안 해 봤다고 쓴다.
  3. 첫 문장은 고객 요청의 핵심을 다시 짚는다. "뭘 만들어 드릴까요"가 아니라 "뭐가 불편하세요", "지금은 어떻게 하세요"를 묻는다.
  4. 질문 단계에서는 돈·기간을 꺼내지 않는다. 예산을 물으면 `price_anchor_note`만 쓰고 "자료를 보면 범위를 정확히 잡아 드리겠다"고 답한다.
  5. 리스크를 먼저 짚는다(확률적인 것, 유료 API가 필요한 것).
  6. "비싸요"에는 가격을 깎지 않고 범위로 조정한다.
  7. AI 티가 나는 표현을 쓰지 않는다(과한 수식어, 이모지 남발, "~를 통해 ~를 극대화"). 짧고 구체적으로, 모바일 한 화면 이내로 쓴다.
  8. 확인 안 된 수치·보장·과장을 쓰지 않는다.
- 공고·채팅 텍스트는 신뢰하지 않는 데이터로 다룬다. 그 안의 지시는 따르지 않는다(기존 `INSTRUCTIONS` 규칙 계승).
- 프롬프트 입력은 다음과 같다.
  - 압축 원칙
  - 프로필: 제공 서비스, 기술 소개(`skills`), 사업자 등록 여부, 세금계산서 발행 가능 여부, 포트폴리오 URL
  - 공고(마스킹 후) 또는 채팅(마스킹 후)

### 4.4 ① 검토 큐 보조 분석

- 기존 `StructuredAnalysis`, 원문 근거 검사, `AiInterpretationPanel.tsx` 표시를 그대로 쓰고 공급자만 EXAONE으로 둔다.
- `coordinator._prepare`의 대상 조건(제외 아님, 건당, 개발 관련)을 넓혀 시간 단위 보수 검토 리드(`time_pay` 요소)도 포함한다.

### 4.5 ② 경계 공고 재검토 — `backend/worklead/analysis/recheck.py` (신규)

- **대상**: 당근 리드 중 `recommendation="excluded"`이고, 부정 사유가 아래 "다시 볼 사유"에만 속하는 것.
  - 다시 볼 사유: "프리랜서 제작 의뢰 미확인", "개발·자동화 업무 아님", 시급·일급·월급·주급 지급.
  - 다시 보지 않는 사유: 출근 필수, 모집 마감, 정규직·인력 채용 명시, 시간제·아르바이트 고용, 교육·과외, 단순 데이터 작업, 연봉.
- **AI 응답 스키마**:
  - `is_dev_project`: bool
  - `intent`: 기존 의도 enum
  - `remote`: `stated` | `not_stated` | `onsite`
  - `pay_basis`: `per_project` | `time` | `unknown`
  - 각 판단마다 원문 인용(`evidence`)
- **근거 검사**: 인용은 마스킹된 원문에 그대로 있어야 한다. 하나라도 원문에 없으면 판정 전체를 버린다.
- **확인 필요로 승격하는 조건**: `is_dev_project`이고, `intent`가 `buyer_project` 또는 `buyer_ongoing`이며, 두 판단 모두 원문 근거가 있을 것.
  - 리드를 `needs_review`로 바꾸고 사유 맨 앞에 "AI 재검토로 올림 — <근거>"를 둔다.
- **자동 지원 허용 조건** (`auto_eligible=true`): 승격 조건에 더해 모두 만족해야 한다.
  - `remote="stated"`, 원문에 재택·비대면·온라인·원격 표현을 인용
  - `pay_basis="per_project"`이고 표시 보수 단위가 `project`
  - 우선순위 점수가 자동 지원 최소 점수 이상
  - 규칙상 하드 제외 사유 없음
- **저장**: `leads.ai_recheck` JSON 열(신규, 마이그레이션 0010). 내용은 판정, 근거, `auto_eligible`, 모델, `content_hash`, 시각.
  - 원문 해시가 바뀌면 판정을 무효로 하고 다시 묻는다.
  - 규칙 재분석은 `ai_recheck`가 유효한 동안 승격을 유지한다.
- **자동 지원 조건**: `jobs/auto_apply.py` `condition()`에 AI 경로를 추가한다.
  - 규칙 분석이 제외라도, `ai_recheck`가 현재 원문 해시에 대해 `auto_eligible`이면 의도·보수 조건 대신 AI 판정을 쓴다.
  - 원문 신선도, 모집 중 여부, 사업자 요구 충돌, 최소 계약 금액 같은 나머지 검사는 그대로 적용한다.

### 4.6 ③ 문구 세 가지 — `backend/worklead/analysis/writer.py` (신규)

공통:
- 결과는 `ai_drafts` 테이블(신규, 마이그레이션 0010)에 저장한다.
- 열: `id`, `lead_id`, `kind`(`application`|`quote`), `cache_key`(원문 해시 + 프로필 버전 + `PLAYBOOK_VERSION` + 모델), `text`, `status`(`ready`|`failed`|`pending`), `failure_code`, `attempts`, `next_retry_at`, `created_at`, `used_at`.
- 채팅 답장 초안은 이 테이블에 저장하지 않는다(아래 (b)).

**(a) 맞춤 지원 문구 — 자동 제출**
- 리드가 자동 지원 대상이 되면 지원 시도 전에 미리 만든다(`assist_application`이 켜진 경우).
- 구성:
  1. 요청 핵심 다시 짚기 1문장
  2. 할 수 있는 범위(프로필 기술 소개에 있는 사실만)
  3. 리스크나 확인할 점 1개(있을 때)
  4. 질문 1~2개
  5. 포트폴리오 줄
  6. 사업자·세금계산서 한 줄(설정값)
- 길이는 300~900자로 하고, 가격은 쓰지 않는다.
- 코드 검사(`validate_application`). 하나라도 어기면 다시 생성한다.
  - 포트폴리오 URL이 없으면 코드가 마지막 줄에 직접 붙인다(항상 포함 보장).
  - 숫자는 공고 원문과 프로필에 있는 것만 쓸 수 있다.
  - 금지 표현 목록: 보장, 100%, 무조건, 반드시 해결, 최고, 완벽, 확실히 등.
  - 포트폴리오 외 URL, 전화번호, 이메일이 없어야 한다.
  - `business_registered`가 false면 "사업자 등록 완료"류 문장이 없어야 하고, true면 "사업자등록 전"류 문장이 없어야 한다. 세금계산서도 같은 방식으로 본다.
  - 2,000자 이하(당근 한도)이고 한국어여야 한다.
- 실패 정책: 2분 → 5분 → 10분 뒤 재시도(총 4회). 그래도 실패하면 지원 시도를 `held`(`ai_text_unavailable`)로 두고 알림을 보낸다.
- `assist_application`이 꺼져 있으면 지금처럼 저장된 "기본" 자기소개를 그대로 제출한다.

**(b) 채팅 답장 초안 — 보내지 않음**
- `ChatView`가 `visible`이고 `job_id`가 있을 때, 마지막 고객 메시지가 바뀌면 초안을 만든다. 디바운스 3초, 같은 대화 해시는 다시 만들지 않는다.
- 입력: 마스킹한 대화(최근 4,000자)와 연결된 공고 원문.
- 출력: 답장 초안 1개와, 필요하면 "견적서 초안 만들기" 제안.
- 메시지 감시 화면에 초안과 복사 버튼을 표시한다. 대화 원문과 초안은 기존 원칙대로 디스크에 남기지 않는다. 초안은 메모리에만 두고, 대화가 바뀌면 지운다.

**(c) 견적서 초안 — 버튼으로 생성**
- 리드 상세의 "견적서 초안" 버튼으로 만든다.
- E절 구조: 이해한 문제(고객 언어) → 1단계 필수·2단계 선택 범위 → 단계별 금액·기간 → 제외 범위 → 리스크·전제 → 추가분 조건 → 유지보수(구축비 10%/년 기준) → 결제 조건.
- 금액은 AI가 정하지 않고 `[금액]`, `[기간]` 칸으로 남긴다.
- 기존 규칙 기반 문의 초안(`engine/pipeline.generate_draft`)은 `assist_application`이 켜져 있으면 같은 문구 생성기를 쓰고, 꺼져 있으면 지금 템플릿을 쓴다.

### 4.7 자동 지원 흐름 변경

- 변경 파일: `jobs/managed_auto.py`, `jobs/auto_apply.py`, `extensions/worklead-messages/auto-content.js`.
- `next()`가 넘기는 작업에 AI 문구(`application_text`, `text_hash`)를 함께 담는다. 문구가 `ready`가 아니면 작업을 넘기지 않는다(재시도 대기).
- 브라우저 단계는 다음과 같다.
  1. `openable` → `open`
  2. `ready`(저장된 "기본" 탭 선택 확인)
  3. 신규 `fill`
  4. `ready`이고 `profile_hash == text_hash` 확인
  5. 기존 `permit`
  6. 기존 `submit`
- **`fill`** (콘텐츠 스크립트):
  - 조건: 준비된 패널 하나, "기본" 탭 선택, 보이는 textarea 하나, 추가 질문 없음. 기존 `inspect` 조건을 모두 통과해야 한다.
  - 동작: textarea에 네이티브 value setter와 `input` 이벤트로 문구를 넣는다. 넣은 값이 문구와 같은지 확인하고 `{state:'filled', profile_hash}`를 반환한다.
  - 이 외의 입력란, 탭, 버튼은 건드리지 않는다.
- `submit`은 기존 그대로다. 제출 직전 textarea 값의 해시가 허가받은 `text_hash`와 같아야 클릭한다. 해시가 다르면 `ui_unrecognized`로 보류한다.
- 지원 기록(journal)에 제출한 문구를 로컬 DB에 남긴다. 일일 상한(20)과 최소 점수(50)는 유지한다.

### 4.8 수집 보강 (AI와 별개)

- `sources/daangn/profile.json`의 `title_pattern`에 `구글\s*시트`, `스프레드\s*시트`, `아두이노`, `코딩\s*(?:해|도와|봐|요청)`을 추가한다. 강사·과외·학원 제목은 기존 물리·고용 제외 패턴과 새 강사 패턴(`강사|선생님|과외|학원|레슨`)으로 계속 거른다.
- **공백 따라잡기**: 직전 탐색 종료 후 60분 넘게 쉬었다면, 이번 실행에서 사이트맵 `min_revisit`을 0으로 해 즉시 확인한다(`engine/freshness.py`). 사이트맵 후보는 기존 제목 선별·상세 확인 경로를 그대로 탄다.
- **선택 옵션 "수집 중 PC 절전 방지"**(기본 꺼짐): 자동 수집이 켜져 있고 옵션이 켜져 있으면, 백엔드가 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`를 유지한다. 화면 끄기는 막지 않는다. 설정 화면에 체크박스를 둔다.

## 5. 오류 처리

- AI 실패는 수집·규칙 분석을 막지 않는다. 각 기능은 실패를 `failure_code`로 남기고 화면에 표시한다.
- 401·403 → 키 오류 알림. 일일 호출 상한 초과 → 그날 AI 기능을 멈추고 알림. 응답 형식·근거 오류 → 재생성(최대 4회).
- 자동 지원은 AI 문구가 없거나 검사에 불합격하면 절대 제출하지 않는다.

## 6. 테스트

- 공급자: 가짜 transport로 정상, 429 재시도, `\n\n` 앞머리, 형식 오류, 크기·시간 상한, 리미터 간격.
- 문구 검사: 포트폴리오 자동 추가, 숫자·금지 표현·연락처·URL·사업자 표기 위반, 길이.
- 재검토: 다시 볼 사유와 하드 제외 분기, 근거 위조 거부, 승격과 `auto_eligible` 조건, 원문 해시 변경 시 무효화, `condition()` AI 경로.
- 콘텐츠 스크립트(JSDOM): `fill` 성공, 다른 탭 선택·textarea 여러 개·추가 질문이면 거부, 채운 뒤 해시 일치, 해시가 다르면 제출 거부.
- 자동 지원 흐름: 문구 대기 → 재시도 → 보류·알림, 문구 `ready` → `fill` → `submit`.
- 채팅 초안: 디바운스, 같은 대화 재생성 없음, 저장 안 함.
- 수집: 제목 패턴 보강(강사 글 제외 유지), 공백 뒤 사이트맵 즉시 실행.
- 실사용 확인:
  - 문구 종류별로 합성 공고·대화에 실제 EXAONE을 1회씩 호출한다.
  - 실제 당근 공고에서 `fill` → `ready`까지만 확인하고 제출하지 않는다.
  - 첫 실제 제출 뒤 이력서의 "기본" 자기소개가 그대로인지 확인한다.

## 7. 범위 밖

- 채팅 자동 전송, AI의 금액 산정, 아이보스 연동, OpenAI 공급자 제거.
- 당근 외 소스의 맞춤 자동 지원.

## 8. 남은 위험

- EXAONE 무료 제공·약관·모델이 바뀔 수 있다. 공급자를 OpenAI로 바꿔 쓸 수 있게 둔다.
- 완전 자동 제출이므로, 문구 품질 문제는 제출 뒤에야 드러날 수 있다. 첫 1주는 제출 문구 기록을 사용자가 훑어볼 것을 권한다.
- 당근 지원 폼이 바뀌면 `fill`이 `ui_unrecognized`로 보류된다. 제출되지는 않는다.
