# 무인 탐색·지원 개선

이번 변경은 `install-20261102-fast-flow` 설치 소스를 기준으로 한다. 작업 중인 M4 분류 변경은 배포에서 제외하고 작업 트리에는 보존했다.

## 수집 순서와 누락 보완

- 지역 피드 요청 실패는 마지막 **성공** 방문 시각을 덮어쓰지 않는다. 네트워크·서버 일시 오류는 1분·2분 뒤 최대 두 번 재시도하며, 이후 해당 지역의 정상 간격으로 돌아간다. 구조 변경·접근 제한에는 이 빠른 재시도를 적용하지 않는다.
- 지역 목록에서 유망 후보 두 건을 먼저 확인한 뒤 다른 지역 목록으로 넘어간다. 남은 상세는 같은 실행의 후속 작업으로 저장한다. 아직 조회하지 못한 후보는 기존 저장 후보 경로에서도 이어받는다.
- 피드 첫 페이지 20건이 채워지고 새 공고가 관찰된 지역은 최대 두 곳을 5분 간격 우선 확인 대상으로 선정한다. 같은 목록만 반복되면 포화 가속을 유지하지 않는다.
- 포화 지역·실패 재시도·기존 우선 지역은 모두 **10분당 최대 8회의 가속 확인** 한도를 공유한다. 요청 간격 6초, 일일 예산 5,500회와 호스트 cooldown은 늘리거나 우회하지 않는다.
- 지역 우선순위에는 최근 데이터에 더 높은 가중치를 주고, 조회당 유효 제작 수요를 반영한다. 같은 공고의 지역 중복은 생산성으로 중복 계산하지 않는다.
- 관련 검색어가 제목에 없는 약한 제작 요청도 한 실행에 최대 2회만 상세 표본 검사한다. 명백한 근로·현장 업무·위험 제목과 좁게 지정한 검색 범위는 제외한다. 표본은 자동 지원 대상 판정이 아니며, 본문 분석과 기존 지원 조건을 그대로 거친다. 미조회 표본을 기록해 다음 실행에서 순환한다.

## 장시간 운영

- 전용 Edge 연결은 최초 5·15·60초 재시도 뒤에도 2분부터 최대 15분까지 지연을 늘려 복구를 계속한다. 정상 창에서 계정 확인·응답 오류가 60초 이상, 세 번 이상 지속되는 경우도 안전하게 다시 연다.
- 백엔드 프로세스의 반복 비정상 종료도 지연 복구한다. 명확한 시작 실패나 데이터·설정 오류는 확인이 필요하므로 무조건 재시작하지 않는다. 종료·수동 재시작 시 오래된 복구 예약은 기존 generation 검사로 무효화한다.
- 로그인 만료·계정 변경·기본 자기소개 변경·사이트 차단·사용자가 누른 중지는 별도로 처리한다. 인증이나 접근 제한을 자동 우회하지 않는다.
- 로그인·사용자 조치가 필요한 중단은 한 번 알리고, 일시 연결 장애는 15분 지속될 때 한 번 알린다. 알린 장애의 복구도 한 번만 기록한다. 일반 앱 종료와 명시적 중지를 구분해 재시작마다 같은 알림이 쌓이지 않도록 했다. 기존 알림 종류·조용한 시간·Windows 알림 선택을 따른다.
- 제출 허가·journal·기존 지원 기록은 유지한다. 제출 후 브라우저가 끊겨도 지원 버튼을 다시 누르지 않고 공식 완료 표시만 대조한다.

## 검증과 한계

설치·검사 증거는 `artifacts/install-20261102-unattended`에 보존한다. 전체 백엔드 검사는 파일 단위 독립 프로세스로 실행하고, 수집한 전체 node 수와 결과 XML의 중복·누락을 대조한다. 순차 실행 중단 기록은 `sequential-interrupted.log`이며 통과 결과로 사용하지 않는다.

전체 회귀 검사에서 CSV/JSON 내보내기를 중간 취소한 뒤 DB 조회 커서가 남아 다음 작업의 `BEGIN IMMEDIATE`가 실패하는 문제가 발견되었다. 스트리밍 조회를 context manager로 감싸 취소·오류에서도 연결 반환 전에 닫도록 수정했다. 기존 취소·전체 행 출력·일관된 스냅샷 검사와 수집 작업 배타성 검사 14개가 수정 후 통과했다. 수정 전 전체 검사 결과는 `before-export-fix-tests`에 별도로 보존했다.

컴퓨터와 앱이 실행 중이고 인터넷 및 당근 로그인 세션이 유효해야 한다. 지역 피드의 공개 지연과 최초 20건 한계가 남으므로 전국 모든 공고의 즉시 발견을 보장하지 않는다. 실제 신규 공고의 게시→발견→제출 시간과 실제 제출 완료는 운영 결과를 별도로 확인해야 한다.
